## 2. 남은 작업

### 2-1. 비행몹 임포트 ★ 선행 조건

`.glb`는 Unity 기본 지원이 아니다(`manifest.json`에 glTF 패키지 없음).

| | 방법 | 판단 |
|---|---|---|
| A | glTFast 패키지 설치 | 패키지 추가 + 리깅 해석이 FBX보다 불안정 |
| **B** | **Blender로 FBX 변환** | **권장** — 기존 4종과 일관, 본 이름 정리 가능 |

**B 선택 시 사람 손이 필요한 부분**(자동화 불가):
1. Blender에서 `.glb` → FBX 내보내기
2. 본 이름 정리 (`Bone_009` → `WingL` 등) — 선택이지만 권장
3. `Assets/_Project/Art/` 배치

이후는 전부 자동화 가능: 프리팹 재구성 · 머티리얼 · 레이어 · 프로파일 연결.

### 2-2. 부위 분리 구현 (파손몹)

**방식 결정 필요**:

| | 방법 | 장 | 단 |
|---|---|---|---|
| A | 프리팹 변형 사전 제작 | 싸고 확실 | 변형 수만큼 프리팹 제작 |
| B | 런타임 스킨 가중치 0 | 조합 자유 | 개체마다 메시 사본 |
| **B′** | **B + 조합별 메시 캐시** | **A의 효율 + B의 자유도** | 구현 약간 복잡 |

> 로봇이라 절단면이 뚫려 있어도 "기계 내부"로 읽힌다 → B 계열의 최대 약점이 이 프로젝트에선 무해.

**파손 부위 확정** (사장님 결정 완료):

```
grunt · soldier · gruntt · soldiert   ← 오른손에 무기. 오른쪽 계열 보존 필수
  Head          가중치 0.4
  LeftShoulder  가중치 1.0    (팔 전체가 딸려 떨어짐)
  LeftForeArm   가중치 0.6
  ✗ RightShoulder/RightArm/RightForeArm/RightHand 는 절대 금지

pinky                                  ← 무기 없음, 제약 없음
  Head · LeftShoulder · RightShoulder

caco                                   ← 날개 한쪽만 보존
  본 확인 후 확정
```

**전선 사양**: 안 끊어짐 · 바닥에 끌릴 길이 · 뿌리 굵고 끝 가늘게 · 금속+구리 · 끝에 스파크

### 2-3. 절단 시스템 충돌 처리

`Dismemberment`는 본이 아니라 **프리팹에서 구운 정적 메시를 평면으로 자른다**(몹 종류당 1개 공유).
→ 팔이 떨어진 개체를 처형하면 **팔이 되살아난 시체**가 잘린다.

**결정: B안** — 처형 시작 순간 전선·조각을 즉시 제거. 처형은 순식간이라 눈에 잘 안 띈다.

### 2-4. 눈 LED 발광

**원인 확정**: 에미션 텍스처는 이미 있는데 머티리얼이 안 쓴다.

```
FootSoldier/Textures/..._texture_emission.png   존재
CrimsonCoreSentinel/Textures/..._texture_emit.png 존재

머티리얼 4종 전부:
  _EmissionMap: (비어 있음)
  _EmissionColor: {0,0,0}
  m_ShaderKeywords: (없음)
```

**작업**:
1. Emission 켜기 + 맵 연결
2. **HDR Intensity 2~4** — 1 이하면 Bloom(threshold 1.05)에 안 걸려 그냥 밝은 빨강일 뿐
3. 에미션 맵이 눈만 밝은지 확인 — 몸 전체가 밝으면 마스킹 필요

**확인 필요**: `headfront` 본이 있다 — 얼굴 앞 장식일 텐데 여기가 LED일 수 있다.

**런타임 제어(선택)** — `MaterialPropertyBlock`이라 드로우콜 안 늘어남:
- 피격 시 깜빡 · 경직 시 점멸
- **돌진 준비 시 밝기 급상승** ← 예지 게임의 텔레그래프로 유효
- 개체마다 눈 색 미세 차이

### 2-5. 텍스처 — "더럽게"

| | 방법 | 판단 |
|---|---|---|
| **A** | **셰이더 그런지 오버레이** | **권장** — 텍스처 1장으로 개체마다 다르게, 드로우콜 유지, 비용 0 |
| B | 텍스처 여러 장 제작 | 정밀하지만 조합 폭발 |

```
최종색 = 원본 × 색변조 × (1 − 오염량 × 그런지노이즈) + 녹/얼룩색 × 오염량
```

개체 생성 시 **오염량·색조·노이즈 오프셋만 난수** → 무한 변형.
`MaterialPropertyBlock` 사용 시 배칭 유지.

**A + 소량의 B 권장**: 전반적 오염은 셰이더, 특징적 자국만 텍스처.

## 5. 발광·오염 셰이더 (`Game/EnemyBody`)

**왜 만들었나**: 에미션 맵이 있는 모델도 있고 없는 모델도 있어(새 비행몹은 없음) 맵에 의존할 수 없었다.
베이스 텍스처에서 **빨강을 직접 추출**하므로 어떤 모델이든 추가 자산 없이 작동한다.

```
빨강강도 = base.r − max(base.g, base.b)
마스크   = smoothstep(임계값, +부드러움, 빨강강도)
발광     = base.rgb × 색조 × 마스크 × 강도
```

**오염(녹·얼룩)**도 같은 셰이더에 넣었다. 절차 노이즈(FBM)라 텍스처가 필요 없고,
개체마다 `_GrungeAmount`·`_GrungeSeed`를 난수로 줘 **같은 몹도 다르게 더럽다**.
발광 라인은 75% 덜 더럽혀 식별 기능이 가려지지 않게 했다.
오염부는 금속성·매끄러움이 함께 떨어져 실제로 녹슨 것처럼 보인다.

전 파라미터가 인스턴싱 버퍼에 있어 `MaterialPropertyBlock`으로 개체별 지정해도 **배칭이 유지**된다.

## 5. 원칙

- **클립**: 발이 땅을 밀거나 실루엣이 크게 바뀌는 것
- **절차**: 상황 변수에 연속 반응하는 것 (시선·피격·경직·호흡·비행)
- 절차는 클립을 **덮어쓰지 않고 위에 가산**. 순서는 `Animator → 절차(LateUpdate) → 최종`
- 몹마다 MonoBehaviour를 붙이지 않는다 — `EntityViews`의 배열 루프에서 처리
- Sim은 건드리지 않는다 (판정·결정론·예지 불변)
