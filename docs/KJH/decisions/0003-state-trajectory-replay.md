# ADR-0003: 상태 궤적 재생 (입력 재생 기각)

- 날짜: 2026-07-18
- 상태: 확정

## 결정

예지 경로 재생 시, 탐색 단계에서 계산한 **프레임별 상태(`PlayerSimState` 전체)를 저장해두고 재생 때 그대로 적용**한다. 재생 중 시뮬레이션을 다시 돌리지 않는다.

## 배경 — "스플라인 vs 입력 재생"은 틀린 대립이었다

처음엔 두 선택지로 봤다.
- 스플라인: 재생 이동을 미리 그린 곡선으로 고정. 플레이어 결정론 불필요.
- 입력 재생(팀원 v1.1): 저장된 입력을 재생 때 다시 시뮬레이션에 먹여 위치 생성. 플레이어 결정론 필수.

그러나 **탐색 단계에서는 어느 쪽이든 플레이어 시뮬레이션이 필수다.** "이 방향으로 질풍참하면 어디 착지하나", "여기서 더블점프하면 2층에 닿나", "이 벽에 벽타기가 되나"는 시뮬레이션해야만 안다. 스플라인을 손으로 그리면 벽을 뚫거나 도달 불가능한 경로가 나온다. 특히 벽타기가 들어가면 스플라인 수작업은 불가능하다.

따라서 진짜 차이는 **탐색 결과를 어떻게 저장하고 재생하느냐**뿐이다.

## 결정 내용

| | 저장 | 재생 |
| --- | --- | --- |
| 입력 재생 (기각) | 입력 시퀀스 | 다시 시뮬레이션 |
| **상태 궤적 재생 (채택)** | 프레임별 상태 전체 | 저장된 상태를 그대로 적용 |

입력 재생은 결과를 버리고 재생 때 다시 계산한다 → **두 번 굴리니 디싱크가 생길 수 있고**, 그래서 "플레이어 위치 2cm 이하" 같은 디싱크 검사가 필요해진다. 한 번만 굴리고 캐시하면 그 검사 자체가 불필요하다.

## 이유

- **디싱크 원천 제거**: 플레이어를 두 번 굴리지 않으므로 플레이어發 디싱크가 원리적으로 없다.
- **Miss 복귀가 자연스럽다**: 저장된 상태에 속도·접지까지 들어 있어, Miss 시 그 프레임 상태를 실제 월드에 주입하면 그 자리에서 자연스럽게 이어진다.
- **용량 문제 없음**: 5초 × 60Hz × ~100바이트 ≈ 30KB, 후보 3개면 ~90KB.

## 전제

Perfect든 Good이든 **계획 행동은 그대로 실행되고 위치가 달라지지 않아야** 한다. Miss만 재생을 끊는다. (GDD 3.7, 팀원 v1.1 4.6과 일치.)

## 남는 요구사항

비트 단위 재현성(두 번 굴려 똑같기)은 불필요하지만, **런타임 컨트롤러와 탐색용 시뮬레이터는 같은 코드여야 한다.** 다르면 예지가 보여준 경로를 실제로 갈 수 없다. 그래서 컨트롤러를 `(상태, 입력) → 새 상태` 순수 함수로 짜고, 상태를 `Transform`/`CharacterController`가 아니라 `PlayerSimState` 구조체에 둔다.

→ 결론: 팀원 v1.1과 **같은 구조(상태 구조체)를 쓰되, 부동소수점 재현성 검증은 뺀다.** 요구 수준이 한 단계 낮다.
