> 여러 아레나 씬을 하나의 마스터 씬으로 이어 레벨을 만드는 도구·절차 문서.
> 이 세션(2026-07-23)에서 만든 것: `ArenaAssemblyTool`, `ArenaRoom`, `ArenaLights`(수정).
>
> **⚠ 조립은 이미 진행됐고 방식이 바뀌었습니다 — 현재 상태는 [마스터씬_인수인계.md](마스터씬_인수인계.md)를 먼저 보십시오.**
> 바뀐 점: NavMesh를 아레나별로 **콘텐츠 프리팹 안에서** 굽고(§7·§89의 "마스터에서 병합"이 아님),
> 예측 그래프만 마스터에서 통합해 굽습니다. 아래 §6 미해결 TODO는 그 결과 **불필요해졌습니다.**

## 0. 레벨 흐름 / 아키텍처 전제

- 흐름: **StartPlace(복도, 스폰) → Arena_1 → 복도 → Arena_2 → 복도 → Arena_3 → 복도 → Arena_4(마지막, 클리어 시 맵 폭발·엔딩)**
- 복도는 몹 없음(잇기만). 첫 스폰은 복도.
- 아레나 진입 → **뒤쪽 게이트 닫힘(가둠)** → 웨이브 전부 클리어 → **앞쪽 게이트 열림(다음 복도로)**.
- **핵심 제약**: 각 아레나 씬은 *완전한 플레이 씬*(Main·카메라·게임플레이 시스템 포함)이라 그냥 못 합친다.
  → 시스템은 마스터에 **하나만**, 각 아레나는 **콘텐츠 프리팹**(지형+웨이브+방+조명+nav데이터)으로.
- **그래프/링크/NavMesh는 각 아레나 씬에서 굽고, 마스터에서 병합**한다(마스터에서 재생성 X).
  → 따라서 nav/예측 데이터는 콘텐츠에 담아 같이 나른다.

## 2. ArenaAssemblyTool — 메뉴 `Tools > Arena 조립`

씬 최상위 오브젝트를 **시스템(마스터에 하나만 유지)** 과 **콘텐츠(아레나별로 떼어낼 것)** 로 분류한다.

**분류 규칙 (`IsBootstrap`)**: 이름이 `[`로 시작(매니저)·`Main`·`_Cameras`·`_Gameplay`·`GameplayVCam`·`PlayerAnchor`·`Directional Light`·`EventSystem`·`Global Volume`/`Post` 시작·카메라 포함 → **시스템**. 그 외 → **콘텐츠**.

### ① 분류 미리보기 (안전, 안 바꿈)
- 현재 열린 씬의 분류를 Console에 출력만 한다. **②·③ 전에 반드시 확인.**

### ② 현재 씬 → 콘텐츠 프리팹
- 콘텐츠 루트들을 `<씬>_Content` 하나로 묶어 `Assets/_Project/Prefabs/Arenas/Content/<씬>_Content.prefab` 생성.
- 원본 월드 위치 유지. 씬은 저장하면 "시스템 + 콘텐츠 프리팹 인스턴스" 상태가 됨.

### ③ 현재 씬 → 마스터 뼈대 복제 (시스템만)
- 현재 씬을 복제해 `Assets/_Project/Scenes/Level_Main.unity` 생성 → 콘텐츠 삭제, 시스템만 남김.
- ⚠ 시스템→콘텐츠 **참조가 끊길 수 있음**(Main·게임플레이에 Missing 필드 생기는지 점검, 콘텐츠 배치 후 재배선).

## 3. ArenaRoom — 방 관리 (아레나 루트에 부착)

**게이트 실물은 만들지 않음.** 웨이브 시작 + 상태·이벤트만 노출 → 회원님 게이트가 구독.

### 플레이어가 "이 아레나 안에 있다" 인식 방식 (중앙 관리자 없음, 분산)
1. 런타임에 생기는 **`PlayerAnchor`**(EntityViews가 만드는 플레이어 렌더 위치)를 이름으로 찾아 캐시.
2. **`zone.ClosestPoint(플레이어) == 플레이어`** 면 존 안 → 내부 판정. (물리 트리거 X — 플레이어가 sim 이동이라 콜라이더가 없을 수 있어 **위치 검사**.)
3. 처음 내부가 되는 순간 → 그 방 `WaveRunner.StartFrom` + `onLock` 발화.
- 즉 "어느 아레나에 있나" = 지금 플레이어를 품은 존을 가진 그 ArenaRoom. **존끼리 안 겹치게**(사이에 복도) 둘 것.

### 인스펙터
- `runner` (비우면 자식 WaveRunner 자동), `zone`(비우면 자기 Collider — Box·isTrigger 권장), `player`(비우면 PlayerAnchor 자동)
- `startOnce`(기본 true), `startWaveIndex`(0), `runAll`(true)
- 이벤트: **`onLock`**(진입·웨이브 시작 → 뒤 게이트 닫기), **`onUnlock`**(전 웨이브 클리어 → 앞 게이트 열기)
- 코드 구독: `event Action OnLock/OnUnlock`
- 상태 읽기: `IsLocked` / `IsCleared` / `IsActive`
- `ReArm()` — 수동 재무장(반복 방)

## 4. ArenaLights — 소환 중 빨강 / 그 외 하양 (아레나 루트에 부착)

- **소환 중(WaveRunner.State.Spawning)에만 빨강(combat)**, 그 외(WaitStart·Watching·Done·Idle) 전부 **하양(idle)**. `fadeSeconds`로 부드럽게 전환.
- 자기 **하위** Light + Emission 켜진 머티리얼만 제어(머티리얼은 아레나별 인스턴스 → 원본 안전, 여러 아레나 이어붙여도 독립).
- **마스터 씬 편의**: 컴포넌트 우클릭 → **`프리셋 → 소환=빨강 / 그 외=하양`** 원클릭 리셋. **프리팹에서 리셋하면 마스터의 모든 인스턴스에 전파.**
- 기존에 배치된 인스턴스는 옛 프리셋(노랑/파랑)이 직렬화돼 있으니, 이 메뉴로 통일.

## 5. 처음부터 끝까지 조립 절차

1. **① 분류 미리보기** — Arena_1~4 각각 열어 시스템/콘텐츠 분류 확인. (아래 "미해결 TODO" 먼저 볼 것.)
2. **② 콘텐츠 프리팹화** — Arena_1~4 + 복도(StartPlace·Corridors) 각각. `Content/`에 생성.
3. **콘텐츠 프리팹에 방 컴포넌트 심기** — 각 `Arena_N_Content` 프리팹 열어 콘텐츠 루트에:
   - `BoxCollider`(isTrigger, 아레나 내부 크기) + `ArenaRoom`(필드 비우면 자동) + `ArenaLights`(우클릭 흰/빨강 리셋)
   - `_Waves`(WaveRunner)에 `ArenaWaves` 설정 배정됐는지 확인.
4. **③ 마스터 뼈대 생성** — 시스템 갖춘 아레나(예: Arena_1) 열고 ③ 실행 → `Scenes/Level_Main.unity`. Main·게임플레이 Missing 참조 점검.
5. **마스터에 조각 배치** — `Level_Main`에 프리팹 순서대로 드래그(StartPlace→Arena_1→복도→…→Arena_4). `V` 버텍스 스냅으로 구멍끼리 맞물림. 시작 지점에 `PlayerSpawnPoint`.
6. **게이트 연결** — 각 아레나 ArenaRoom: `onLock`→뒤 게이트 닫기, `onUnlock`→앞 게이트 열기. **Arena_4만 `onUnlock`→맵 폭발·엔딩**.
7. **NavMesh·예측 그래프** — 각 아레나 씬에서 구운 데이터를 콘텐츠로 나르고 마스터에서 병합(재베이크 아님).
8. **Build Settings** — `Level_Main`을 활성 씬으로.

### 플레이 검증
StartPlace 스폰 → Arena_1 진입(조명 빨강·뒤 게이트 닫힘·몹 소환) → 소환 끝 하양 → 전멸 시 앞 게이트 열림 → … → Arena_4 클리어 시 폭발.

## 6. ⚠ 미해결 TODO (다음 세션에서 반드시)

**ArenaAssemblyTool 분류 버그**: `[TraversalLinks_Auto]`(층이동 링크 = `Game.View.TraversalLink` 데이터)가 **대괄호라는 이유로 "시스템"으로 잘못 분류**됨. 이건 **아레나별로 구운 nav 데이터라 콘텐츠로 가야** 마스터에서 병합됨.

- Arena_1 ① 미리보기 실제 결과: 시스템에 `[TraversalLinks_Auto]`(×2 중복도 있음)가 들어가 있었음. `_Links`·`NavMeshSurface`는 콘텐츠로 올바르게 감.
- `[NavMeshDebugView]`는 순수 디버그라 시스템 유지가 맞음.

**수정 방향(합의됨, 미적용)**: `IsBootstrap`에 최우선 규칙 추가 —
루트가 **`TraversalLink` / `NavMeshSurface` / `ArenaMapAuthoring`** 컴포넌트를 하나라도 품으면 → **무조건 콘텐츠**(대괄호여도).
→ `[TraversalLinks_Auto]`·`_Links`·`NavMeshSurface` = 콘텐츠(구운 데이터 그대로), 디버그·매니저류 = 시스템 유지.

```csharp
// IsBootstrap 맨 위에 추가할 것(컴포넌트 이름 문자열로 검사 — asmdef 결합 회피):

```
