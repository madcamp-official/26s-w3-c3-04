# 웨이브 시스템 설계

> **상태: 설계 확정, 구현 전.** (스폰 마커 방향표시 도구만 구현 완료.)
> 기존 몹/스폰 시스템은 **전부 갈아엎고** 이 설계로 새로 만든다.

## 0. 현재 상태 (출발점)

### 이미 있는 것
| 항목 | 내용 |

| **웨이브 조합 초안** | [레벨_구성_뼈대.md](레벨_구성_뼈대.md) — 아레나별 W1~W3 몹 조합 (확정 아님, 맵 만들며 튜닝) |

### 버릴 것 / 없는 것
- **현행 스포너 = 웨이브 아님.** `Main.SpawnTick`이 **45틱(0.75초)마다 한 마리씩, 상한 40**을 지점 순번대로 흘리는 단순 트리클. → 교체 대상.
- `SimWorld`의 `waveId` / `spawnLocked` / `mapVersion` 필드는 **해시·예측 잠금용 껍데기**일 뿐 게임 로직에 안 쓰임.
- 웨이브 트리거·전멸판정·문 잠금·마커 연동·스폰 시퀀스 — **전부 미구현.**

## 1. 아레나 루프 (레벨 뼈대가 요구하는 것)

```
아레나 진입 → 문 잠금 → W1 → (진행조건) → W2 → (진행조건) → W3 → 최종 조건 → 문 해제
```
- **아레나** = 가둠 + 웨이브 + 클리어. **복도** = 안 가둠, 웨이브 아님(사전 배치 / 근접 스폰).
- 아레나당 보통 **3웨이브**. 아레나가 진행될수록 몹 종류 추가(근 → 돌 → 공 → 전부 → 보스).
- 몹 약칭: 근·원·돌·공 / 근층·원층(층이동 변종) / 대(대형).
  기존 3축(CombatType × MobilityType × SizeClass)으로 표현 가능.

## 2. 데이터 구조 (확정)

```
ArenaWaves                       ← 아레나 루트(또는 _Waves 자식)에 부착
├─ waves[]                       웨이브 1, 2, 3 …
│   └─ Wave
│      ├─ 시작 지연(초)           이 웨이브 시작 전 대기
│      ├─ 기본 스폰 간격(초)      ← 웨이브마다 다르게 설정 가능
│      ├─ entries[]              ← 배열 순서 = 스폰 순서
│      │    └─ SpawnEntry
│      │       ├─ cube (Transform)   위치 + 방향(forward) 제공
│      │       ├─ kind (몹 종류)
│      │       └─ 간격 오버라이드(선택)  비우면 웨이브 기본값 사용
│      └─ 진행조건 { 방식, 값 }
└─ 마무리정리 { … §5 }
```

### 설계 원칙
- **위치는 전부 수동 지정. 랜덤 없음.** 각 entry가 **특정 cube**를 참조한다.
- **순서 = entries 배열 순서.** "근·원·근·원 번갈아" = 그 순서로 나열.
- **지연 2단 구조**: 웨이브 기본 간격 + 스폰별 오버라이드. 매번 안 적어도 되고, 필요하면 개별 조정.
- **동시 스폰** = 간격 0 (직전 것과 같이 나옴).
- **지연 단위**: **Inspector에는 초로 입력**, 내부에서 **틱으로 변환**(60틱 = 1초). 작업은 직관적, 시뮬은 정확.

### 왜 "cube에 웨이브 태그"가 아니라 "중앙 순서 목록"인가
순서를 제어하려면 **리스트**가 필수다. cube마다 순서 번호를 손으로 매기면 재정렬이 지옥이 된다.
리스트는 드래그로 재정렬된다. → **위치는 공간에서(cube), 순서는 리스트에서.**

### 배치 경로 (직관성)
```
Arena_3
├─ _SpawnBox      (cube 마커 56)
├─ _Waves         ← ArenaWaves 컴포넌트
└─ _Environment …
```
- 아레나 프리팹을 열면 **그 아레나의 웨이브가 바로 거기** 있다.
- cube 참조가 **같은 프리팹 내부**라 참조가 깨지지 않는다.

## 3. 웨이브 진행 조건 (전멸 강제 아님)

```
Wave.진행조건
 ├─ 방식: 전멸 | 남은 수 ≤ N | 남은 비율 ≤ P%
 └─ 값 (N 또는 P)
```
- 예: 웨이브1 = "남은 3마리" → **3마리 남는 순간 웨이브2 즉시 시작.**
- **웨이브가 겹친다**: 이전 잔당 + 새 웨이브가 동시에 존재. 압박 유지가 목적이므로 의도된 동작.
- **카운트 기준**: 스폰된 **적마다 자기 웨이브 번호를 태그**하고, **그 웨이브 소속만** 센다.
  (전체 생존 수가 아님.) 비율(%)의 분모 = **그 웨이브가 스폰한 총량.**

## 4. 스폰 연출·거동 (배관 + 펄스)

### 연출 흐름
마커 자리에 **열렸다 닫히는 애니메이션이 있는 배관**을 배치. 몹이 **"띠용"** 하고 튀어나온다.

### 거동 규칙
- 스폰 시 **배관 바깥 방향(마커 forward)으로 펄스**(초기 속도)를 받는다.
- **지상몹**: 펄스 후 포물선 비행 → **착지(grounded)할 때까지 공격 불가** → 착지하면 정상 AI.
- **공중몹**: 착지 개념 없음 → 펄스 후 **짧은 타이머 뒤** 공격 허용.

### Sim / View 분리
| 계층 | 담당 |
|---|---|
| **Sim** (결정론) | 펄스 초기 속도, 탄도 비행(중력·grounded), **착지까지 무공격 게이트**, 공중몹 타이머, 착지 후 정상 AI 복귀 |
| **View** (비결정) | 배관 열림/닫힘 애니, "띠용" VFX·사운드 — sim으로 되먹임 없음 |

### 구현 메모
- 기존 `traversalPhase.Airborne` / `descentPhase` / `ResolveVertical`(중력·grounded)의 메커니즘을 **재활용 가능**.
- 스폰은 현재 View(`Main`)가 `world.AddEnemy()`로 sim에 주입 → **`AddEnemy`가 초기 속도 + launched 상태를 세팅**하도록 확장.
- **결정론 주의**: 펄스는 **고정값**. `Random` 금지. 스프레드가 필요하면 **sim 상태(틱·인덱스)로 시드**해야 예측이 안 깨진다.
- **예측 상호작용**: 이미 스폰돼 날아가는 몹은 예측이 앞으로 결정론적으로 정확히 굴린다. 단 **예측 재생(Following) 중엔 새 스폰이 잠김**(기존 `spawnLocked`) — 그대로 유지.
- **시퀀싱**: sim이 틱T에 스폰 → view가 등장을 보고 배관 애니·VFX 재생. 배관을 **먼저 열고** 몹이 나오게 하려면 view가 애니를 선재생 후 스폰을 트리거.

## 5. 마무리 정리 (낑김·튕김 대비, 소프트락 방지)

몹이 지형에 낑기거나 밖으로 튕겨 **클리어 불가**가 되는 것을 막는 안전장치.

```
ArenaWaves.마무리정리
 ├─ 사용 여부
 ├─ 발동: 남은 수 ≤ N        (마무리 국면에서만 동작)
 ├─ 대상 조건: 안 보임 AND 거리 ≥ D AND 그 상태가 T초 지속
 └─ 처리: 자동 처치(기본) | 아레나 안으로 재배치(옵션)
```

### "안 보임" 판정
```
안 보임 = ( 시야각(프러스텀) 밖  OR  LOS 막힘(레이캐스트) )
```
- **시야각 밖**: 플레이어 뒤에 있음.
- **LOS 막힘**: 시야 안이지만 기둥·컨테이너·벽에 **가려짐**. → **레이캐스트로 판정.**
  - 기존 [`PhysicsCollision.HasLineOfSight(from, to)`](../../PrecogPrototype/Assets/_Project/Bridge/PhysicsCollision.cs) 재사용.
- **다중 지점 검사**: 몸통 **머리·중심·발** 여러 점으로 레이를 쏴 **전부 막혔을 때만** "안 보임".
  중심 하나만 보면 **얇은 기둥에 몸통 가운데만 가려진 몹**을 오판해 눈앞에서 지워버릴 수 있다.

### ⚠ 정직한 경고
- **이건 안전장치이지 버그 해결이 아니다.** 낑김·튕김의 **근본 원인**(길찾기·겹침 밀침·낙하)은 별도로 고쳐야 한다.
- 자동 처치가 그 문제를 **가려버리면 영영 못 찾는다.**
- → **발동할 때마다 로그를 남긴다**(위치·몹·상황). 안전장치는 돌면서 **진짜 버그도 추적**한다.
- **재배치**는 처치보다 전투를 유지시킨다(그냥 죽이면 난이도가 살짝 내려감). 기본은 처치, 옵션으로 재배치.

## 6. 아키텍처 결정

| 요소 | 위치 | 이유 |
|---|---|---|
| **웨이브 런타임**(스폰 진행·조건 감시·정리) | **View** | 현재도 스폰이 View(`Main.SpawnTick`)에서 sim으로 주입되고 예측 재생 중엔 잠기는 구조라 **기존과 일관**, 가장 단순. 나중에 예측이 스폰까지 봐야 하면 Sim으로 이전 가능. |

## 7. 네이밍·정리 규약

- **데이터를 GameObject 이름에 넣지 않는다.** 웨이브·종류는 **컴포넌트 필드**에 저장.
  이름에 넣으면 오타·중복·stale(cube를 옮기면 어긋남) 문제가 난다.
- **좌표형 이름(예: `1,1`) 사용 안 함.** cube를 조금만 옮겨도 어긋나고, 실제 좌표는 Inspector가 이미 보여준다.
- 웨이브 시스템은 **cube를 이름으로 참조하지 않는다**(entry가 Transform 참조를 직접 들고 있음) → 이름 규칙 자체가 불필요.
- 이름은 **식별·정리용으로만 가볍게.** 공간 구분은 이미 부모 그룹(`_Ceiling` / `_Wall_*`)으로 되어 있음.
- **그룹용 빈 오브젝트는 Position (0,0,0) / Rotation 0 / Scale (1,1,1).**
  특히 **부모 Scale이 1이 아니면 자식이 왜곡**된다. (부모를 두면 Inspector 위치가 로컬 좌표로 바뀌어 소수점이 되는 것은 정상 — 월드 위치는 안 변함.)
- 어느 cube가 어느 웨이브·종류인지는 **이름이 아니라 색/기즈모**로 본다.

## 8. 저작(authoring) 도구

entries에 cube를 하나씩 드래그하는 건 번거로우므로:
- **씬에서 cube 다중 선택 → "웨이브 N에 추가"** → 선택한 cube들이 해당 웨이브 entries에 append.
- 그 후 리스트에서 **종류·간격·순서**만 조정.
- → **위치는 공간에서(직관), 순서는 리스트에서(정확).**
- (선택) 웨이브·종류별로 cube를 다른 색으로 칠해 배치를 한눈에 보기.

## 9. 구현 순서 (제안)

1. `ArenaWaves` 컴포넌트 (§2 구조).
2. 웨이브 런타임 — 시작 → entries 순서·간격대로 스폰 → 진행조건 감시 → 다음 웨이브 → 최종 클리어(문 해제 훅).
3. 적에 **웨이브 태그** 부여(§3 카운트용).
4. 저작 툴 (§8).
5. 스폰 거동(펄스·무공격 게이트) — Sim 확장 (§4).
6. 마무리 정리 (§5).
7. 배관 연출 — View (§4).
8. 기존 `Main.SpawnTick` 트리클 스포너 제거·교체.

> 기존 스포너는 **건드리지 않고 새로 만든 뒤**, 동작 확인되면 교체한다.
