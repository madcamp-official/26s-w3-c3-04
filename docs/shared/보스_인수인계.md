## 0. 한 줄 요약

빛나는 구 오브가 부유 추격 → 차지 → **굵은 추적 레이저를 n초 발사**(지형에 **부분 차단**). 플레이어는 엄폐·이동으로 회피. **보스는 지금 무적/스크립트**(피격·죽음 배선 없음, 패턴·연출만). 소환: 개발 콘솔 **`spawn boss`** / **`solo boss`**.

전역 **무적시간(i-frame)** 도 이때 정식 추가됨(빔이 연속이라 필수, 모든 적 피해에 적용).

---

## 1. 구현·검증 완료된 것 (동작 확인함)

런타임 실측으로 확인: 보스 소환 → Chase→Windup→Fire→Recovery 순환, 빔이 플레이어 추적·렌더(하위빔 다발), 지형이 단면 일부만 가리면 **그 부분만 막히고 나머지는 샘**, 무적시간이 빔 피해를 ~45틱당 1로 조절(hp 3→0), 보스는 피격 무시.

### 계층별 요약
- **Sim(결정론)**: `MobilityType.Orb` + `EnemyBrain.StepBoss`. 상태머신은 기존 `EnemyState`(Chase/Windup/Fire/Recovery) 재사용. 빔 방향은 `EnemyAI.beamDir`.
- **피해**: 빔이 플레이어에 닿으면 기존 히트 큐(`QueuePlayerHit`)에 매 틱 1 큐잉 → `CombatResolve`의 무적시간이 실제 간격 조절.
- **View(연출)**: `ViewKind.Orb` = 절차적 발광 구 + `BossView`(하위빔 LineRenderer 다발). 프리팹 없이 자족.

## 3. 현재 상수값 (전부 튜닝 대상)

### 무적 (`CombatConfig`)
- `PlayerInvulnTicks = 45` (0.75s @60Hz) — **핵심**: 빔 완전노출 시 체감 피해량. HP=3.

### 보스 (`AIConfig`)
| 상수 | 값 | 의미 |
|---|---|---|
| `BossHoverOffset` | 3.0 | 플레이어 y + 이만큼 위 부유 |
| `BossBandMin` / `BossBandMax` | 8 / 16 | 선호 거리 밴드(밖이면 접근/후퇴) |
| `BossEmitterHeight` | 0 | 빔 발사점(e.pos 기준 위) |
| `BossChargeTicks` | 60 (1.0s) | 차지 텔레그래프 |
| `BossFireTicks` | 180 (3.0s) | **빔 지속(n초)** |
| `BossRecoverTicks` | 90 (1.5s) | 발사 후 쿨 |
| `BossChargeTurnRate` | 90 도/s | 차지 중 예비 추적 |
| `BossBeamTurnRate` | **55 도/s** | **발사 중 추적 각속도 — 회피 난이도 핵심** |
| `BossBeamRange` | 45 | 빔 최대 길이 |
| `BossBeamRadius` | **1.8** | 빔 반지름(판정·시각 공통) |
| `BossBeamDamage` | 1 | 접촉 피해(무적이 간격 조절) |

- `EntityViews.BossVisualScale = 5.0` (오브 크기, 실측 스케일 ~8.6)
- `BossView` 하위빔 = **9개**(중앙 굵은선 1 + 바깥 링 R×8). 폭: 중앙 `R*1.6`, 링 `R*0.5`. (`BuildCoords`/`Set`에서 조정)
- **Sim 피해 표본 = 5개**(중심+±Pr·u/v, `BeamHitsPlayer` 내 인라인). View 하위빔 수와 별개.

## 4. 부분 차단 레이저 — 어떻게 도는가 (중요)

굵은 빔을 **단면 평행 하위광선 다발**로 본다. 각 하위광선이 독립적으로 지형까지 레이캐스트 → 단면 일부만 가려지면 그 부분만 막히고 나머지는 샌다.

- **Sim 피해** (`BeamHitsPlayer`, `EnemyAI.cs`): 빔 전체가 아니라 **플레이어가 차지하는 단면 영역만** 5표본 레이캐스트(예측 포크 비용 억제). 표본 **하나라도** 안 막히고 플레이어 거리까지 도달하면 피해("조금이라도 새면 맞음"). 축 수직 기저 `BeamBasis(u,v)`로 표본 위치 생성.
- **View 연출** (`BossView.Set`): 단면 위 9개 하위빔이 각자 `Physics.Raycast`(sim과 같은 `DefaultRaycastLayers`)로 자기 길이만큼 그려짐. **sim과 같은 기저 규칙**을 써서 보이는 것과 판정이 대체로 일치.
- 비용: 발사 중 sim 틱당 최대 5 레이캐스트(예측 포크에서 배가). View는 프레임당 9(포크 무관).

## 5. 소환·테스트

콘솔:
- **`spawn boss`** — 보스 한 마리 추가
- **`solo boss`** — 전부 지우고 보스만(자동소환 off) → **보스 테스트에 이상적**

주의(테스트 함정):
- 보스가 밴드 안(8~16m)+**시야(LOS)**여야 차지·발사한다. 너무 가까이(6m) 소환하면 벽으로 후퇴하다 막혀 발사 안 할 수 있음(실전 아레나에선 멀리서 접근하므로 문제 없음).
- 스폰 지점과 플레이어 사이에 지형이 있으면 시야 막혀 발사 안 함(정상 — "지형 가로막힘"이 작동하는 것).

## 6. 아직 안 된 것 / 다음 할 일

1. **보스 처치(HP·죽음·연출)** — 지금 무적/스크립트. 열려면:
   - `CombatResolve.HitEnemy`의 `if(mobility==Orb) return;` 제거.
   - 그다음 HP·피격 반응·파괴 연출을 설계(대형 코어라 글로리킬과 다른 처리가 어울릴 수 있음).
2. **아트** — 오브·빔이 절차적(URP Unlit HDR). 진짜 프리팹·머티리얼로 교체 여지.
   - **Bloom**: URP 볼륨에 Bloom이 있어야 발광이 후광으로 번짐(현재 없으면 밝은 플랫 색으로만 보임). 볼륨에 Bloom 추가 권장.
3. **예측(예지) 오버레이에 빔 표시** — 이번 범위 밖. 예지로 빔 궤적을 미리 보여주려면 별도 작업.
4. **예측 비용** — 발사 중 sim 레이캐스트가 틱당 최대 5개라 포크에서 예측 부하 상승. 무거우면 `BeamHitsPlayer` 표본을 3으로 줄이거나 발사 중 예측 품질 하향.
5. **호버 높이 튜닝** — 오브가 가끔 낮게(바닥+여유) 안착. `BossHoverOffset`/`FlyMove` 수직 수렴 조정.
6. **결정론 정식 테스트 미실행** — 해시는 배선했고(invulnTicks·beamDir) StepBoss/BeamHitsPlayer는 결정론 연산만 쓰지만, **헤드리스 이중재생 해시 비교 테스트는 아직 안 돌림**. `Sim/Tests`(Game.Sim.Tests.asmdef)에서 보스 포함 시나리오로 한번 돌려볼 것.

## 7. 결정론 메모 (계약 준수 상태)

- `invulnTicks`: player struct라 Snapshot 자동 복사 + `CombatHash.MixPlayer`에 포함. ✅
- `beamDir`: enemies Array.Copy 자동 + `AIHash.MixAI`에 포함. ✅
- `StepBoss`/`BeamHitsPlayer`: `svc.Collision.Raycast`(정적 지형) + 플레이어 위치 + 순수 수학(`Vector3.RotateTowards`, 고정 표본 오프셋)만. **`Time.deltaTime`/`Random`/유니티 물리 직접호출 없음**(dt는 `SimConfig.TickDelta` 인자). ✅
- 새 배열 없음 → WorldBufferPool/Snapshot 추가 작업 없음. ✅

## 8. ⚠️ 환경 설정 변경 (다음 세션이 알아야 함)

**Enter Play Mode Options를 켜고 Domain Reload를 껐다**(Project Settings ▸ Editor). `ProjectSettings/EditorSettings.asset`에 직렬화되므로 **다음 세션도 이 설정을 물려받는다.**

- 효과: 플레이 버튼 진입이 거의 즉시(도메인 리로드 생략). 씬 리로드는 유지.
- **대가**: 정적(static) 상태가 플레이 사이에 리셋 안 됨. 이 프로젝트는 대체로 안전함이 확인됨(패널은 `FindObjectByType` 가드, 리스트는 OnEnable/OnDisable 해제, 캐시는 Resources 에셋, sim은 매 플레이 새 SimWorld). 남는 부작용:
  - F-패널 **미저장** 튜닝값이 다음 플레이에 남음(저장값은 로더가 재적용).
  - 파손변형 RNG(`EntityViews.damageRng`) 리셋 안 됨(연출만).
  - 일회성 진단 경고·카운터 리셋 안 됨(무해).
- **새 코드 규칙**: 정적 이벤트 구독은 `OnDisable`에서 `-=`, 런타임 객체 담는 정적 캐시는 정리, "매 플레이 리셋" 전제 정적 플래그는 `[RuntimeInitializeOnLoadMethod]`에서 초기화.
- 되돌리려면 `EditorSettings.enterPlayModeOptionsEnabled = false`(또는 Project Settings UI).

상세: 이 세션 대화 참조(부작용 조사 결과).
