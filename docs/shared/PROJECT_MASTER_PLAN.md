# 미래 잔상 예측 액션 — 전체 개발 통합 계획서

## 0. 최우선 플레이 규칙 — 예측 리듬 실행

이 프로젝트의 예측 결과는 관람용 자동 재생이 아니다. 플레이어는 선택한 미래의
잔상 노드를 리듬게임처럼 따라가며 각 노드가 요구하는 액션을 직접 입력해야 한다.
이 규칙은 선택 기능이 아니라 게임의 핵심 플레이 루프이자 필수 완료 조건이다.

용어는 다음처럼 고정한다.

- **예측 프리뷰**: 시간이 멈춘 동안 후보 미래와 잔상 노드를 보여주는 단계
- **예측 리듬 실행**: 후보 선택 후 잔상 타이밍에 맞춰 액션을 입력하는 실제 플레이 단계
- **상태 궤적 적용**: 디싱크 방지를 위해 저장된 `SimWorld`를 틱별로 적용하는 내부 구현
- **자동 재생**: 사용하지 않는 표현. 플레이어 입력 없이 성공하는 기능으로 오해되므로 금지

예측 리듬 실행의 규칙은 다음과 같다.

1. 선택한 후보의 이동, 시선, 적 행동, 전투 결과는 저장된 월드 상태 궤적을 따른다.
2. 경로 위에는 0.5초 간격의 잔상과 필수 액션 아이콘을 표시한다.
3. 플레이어는 대시, 점프, 평타, 타깃 런지를 판정 창 안에 직접 입력한다.
4. `Perfect`와 `Good`은 계획된 궤적을 계속 적용하며 판정 점수와 연출만 달라진다.
5. `Miss`는 예측 리듬 실행을 즉시 중단한다.
6. 중단 시 그 틱까지 적용된 실제 `SimWorld`를 유지하고 일반 직접 조작으로 복귀한다.
7. 잔상은 단순 경로 장식이 아니라 다음 위치, 다음 액션, 입력 타이밍을 동시에 전달한다.

따라서 “월드 전체 상태 궤적 재생”은 내부 일관성 보장 방식이고,
“예측 리듬 실행”은 플레이어가 경험하는 게임 규칙이다. 두 개념을 같은 의미로 쓰지 않는다.

## 0. 프로젝트 목표

좁은 수직형 아레나에서 플레이어가 칼과 이동기를 사용해 적 웨이브를 상대한다. 난전이 감당하기 어려워지는 순간 예지를 발동하면 시간이 멈추고, 시스템이 현재 월드 상태에서 생존·처치에 유리한 미래 경로를 계산한다.

플레이어는 제시된 경로를 선택한 뒤 잔상에 맞춰 대시·점프·평타·타깃 런지를 입력하며 계획을 실행한다. 입력에 실패하면 그 시점의 실제 상태에서 예측 리듬 실행과 궤적 적용을 끝내고 직접 조작으로 복귀한다.

핵심 경험:

```text
직접 전투
→ 패닉
→ 시간 정지
→ 미래 경로 확인
→ 경로 선택
→ 잔상을 따라 콤보 실행
→ 위기 돌파
```

핵심 기술 목표:

```text
같은 초기 상태
+ 같은 입력 또는 같은 확정 궤적
+ 같은 시뮬레이션 규칙
= 예측에서 본 것과 동일한 실행 결과
```

## 1. 최종 MVP 범위

### 반드시 구현

- 1인칭 이동과 마우스 시점
- 더블 점프
- 4방향 대시
- 근접 평타
- 우클릭 타깃 런지
- 근접 적 1종
- 명확한 적 공격 Windup/Active/Recovery
- 적 HP·스턴·사망
- 고정 아레나 1개
- 수직 이동 경로와 Drop Link
- 웨이브 3개 이상
- 시간 정지와 월드 스냅샷
- 2~3초 미래 탐색
- 후보 경로 1개 이상
- 0.5초 잔상과 경로선
- 대시·점프·평타·런지 액션 이벤트
- Perfect / Good / Miss
- Miss 시 현재 상태에서 일반 조작 복귀
- 결정론 또는 상태 궤적 재생 검증

### 이번 버전에서 제외

## 2. 전투 시스템 확정안

### 2.1 4방향 대시

| 항목 | 규칙 |
| --- | --- |
| 방향 | 카메라 기준 전·후·좌·우 |
| 피해 | 없음 |
| 용도 | 회피와 위치 조정 |
| 방향 결정 | 시작 순간 고정 |
| 충전 | MVP는 1회 권장 |
| 쿨타임 | 약 1초에서 시작 후 튜닝 |
| 무적 | 초기 버전 없음 |

대시는 항상 정답이 되지 않도록 쿨타임을 둔다. 예측기는 대시를 접근에 쓸지, 회피에 남길지를 판단한다.

### 2.2 평타

| 항목 | 규칙 |
| --- | --- |
| 입력 | 좌클릭 |
| 판정 | 근거리 정면 부채꼴 |
| 피해 | 1 |
| 상태 | Windup → Active → Recovery |
| 타격 | 공격 시퀀스당 적 1회 |
| 역할 | 런지 후 마무리 또는 근접 대응 |

### 2.3 타깃 런지

| 항목 | 규칙 |
| --- | --- |
| 입력 | 우클릭 |
| 대상 | 거리 내 정면 적 |
| 초기 범위 | 1.5~8m |
| 초기 각도 | 좌우 약 30도 |
| 시야 | LOS 필수 |
| 층 | 초기에는 같은 층만 |
| 피해 | 1 + 짧은 스턴 |
| 쿨타임 | 약 2초에서 시작 |
| 무적 | 없음 |
| 타깃 고정 | 시작 순간 `entityId` 고정 |
| 도착점 | 대상 앞 유효 지점 |

타깃 동률:

```text
화면 중앙과의 각도
→ 거리
→ entityId
```

### 2.4 기본 콤보

```text
타깃 런지
→ 피해 1 + 적 스턴
→ 평타
→ 일반 적 처치
→ 4방향 대시로 이탈
```

이 콤보가 직접 플레이에서도 재미있고, 예측 경로에서도 반복 가능한 핵심 문법이 되어야 한다.

### 2.5 적 공격

```text
Approach
→ AttackWindup
→ AttackActive
→ AttackRecovery
```

- Windup 진입 순간 공격 방향 고정
- Windup 중 플레이어를 무한 추적하지 않음
- 공격 범위와 텔레그래프가 육안으로 읽혀야 함
- Recovery 동안 플레이어가 반격 가능
- 예측과 실제가 동일한 상태 머신 사용

## 3. 시스템 아키텍처

```text
Game.View
  입력 · 카메라 · 모델 · 애니메이션 · HUD · VFX · 사운드
                         │
                         ▼
Game.Bridge
  Unity Physics · 맵 데이터 베이크 · 씬 어댑터
                         │
                         ▼
Game.Sim
  플레이어 · 적 AI · 전투 · 이동 · Navigation 상태 · 월드 해시
                         │
                         ▼
Game.Prediction
  행동 생성 · Beam Search · 평가 · 후보 데이터 · 재생 계획
```

### 책임 규칙

#### `Game.Sim`

- 모든 실제 게임 판정
- 60Hz 정수 틱
- GameObject, Transform, Animator 직접 참조 금지
- 동일 상태와 입력에 동일한 결과

#### `Game.Bridge`

- Unity Physics 쿼리
- 씬 Collider와 Navigation 데이터 연결
- 실행 중 Sim이 요구하는 제한된 서비스 제공

#### `Game.Prediction`

- `SimWorld` 복제
- 행동 후보 생성
- 미래 시뮬레이션
- 후보 평가와 정밀 재검증
- View 의존 금지

#### `Game.View`

- 상태를 화면에 표현
- 입력을 `InputCmd`로 변환
- 애니메이션·VFX·사운드
- 독자적인 이동·공격·피해 판정 금지

## 4. 기능 개발과 디자인 투입의 원칙

디자인은 기능이 안정된 뒤 한 번에 넣는 것이 아니라, 검증에 필요한 최소 표현부터 단계적으로 교체한다.

```text
논리 규격 확정
→ 단순 도형으로 기능 검증
→ 실루엣과 색으로 가독성 검증
→ 임시 모델로 스케일 검증
→ 최종 모델·애니메이션 교체
→ VFX·사운드·라이팅 마감
```

### 디자인보다 먼저 고정할 규격

- 플레이어 캡슐 높이와 반지름
- 적 캡슐 높이와 반지름
- 이동 속도
- 대시 거리와 시간
- 평타 거리·각도
- 런지 거리·각도·도착 간격
- 적 공격 범위와 Windup 시간
- 문·통로 최소 폭
- 계단과 경사 규격
- 층 높이
- DropStart와 DropLanding

최종 모델은 이 규격에 맞춘다. 모델 크기에 맞춰 게임 판정을 임의로 변경하지 않는다.

## 5. 그레이박스 단계

### 5.1 표현 규칙

| 대상 | 표현 |
| --- | --- |
| 플레이어 | 숨겨진 캡슐 또는 단색 캡슐 |
| 근접 적 | 빨간 캡슐 |
| 스턴 적 | 노란 캡슐 |
| 공격 Windup | 주황색 |
| AttackActive | 밝은 빨간색 |
| Recovery | 파란색 |
| 런지 가능 적 | 흰색 외곽선 또는 링 |
| 예측 잔상 | 반투명 청록 캡슐 |
| 예측 경로 | LineRenderer |
| Drop Link | 노란 선과 착지 구체 |
| 벽·바닥 | 회색 Cube |

### 5.2 그레이박스 완료 조건

- 이동·점프·대시가 의도대로 작동
- 적 추격과 공격이 읽힘
- 대시로 공격을 회피 가능
- 런지 타깃이 예상대로 선택됨
- 런지 도착점이 벽 안에 들어가지 않음
- `런지 → 평타 → 처치` 가능
- 적 4~8마리 난전이 실제로 위험함
- 예측 없이도 기본 전투가 가능함
- 예측을 쓰면 생존 가능성이 체감상 올라감

그레이박스 완료 전에는 최종 캐릭터 리깅·고급 VFX·복잡한 환경 에셋 배치를 우선하지 않는다.

## 6. Navigation과 충돌 정리

### 6.1 Navigation

Unity NavMesh는 제작 보조로 사용하고, 시뮬레이션은 정적 노드 그래프를 사용한다.

```text
ArenaNavNode
ArenaNavLink
Walk / Ramp / Stair / Drop
levelId
```

맵 로드 시 다음을 사전 계산한다.

```text
nextNodeTable[current, destination]
distanceTable[current, destination]
```

동률:

```text
낮은 총 비용
→ 낮은 nextNodeId
→ 낮은 linkId
```

### 6.2 충돌

MVP에서는 정적 Unity Physics 쿼리를 허용한다.

- 단순 Cube Collider 위주
- 동적 Rigidbody 금지
- 런지 시작 시 경로와 도착점 한 번 검사
- Beam Search 중 정밀 Physics 호출 최소화
- 최종 후보만 실제 `CharacterMotor + ICollision`로 재검증

복잡한 Synty 메시를 넣더라도 실제 게임 충돌은 단순 프록시 Collider를 별도로 유지한다.

## 7. 예측 시스템 개발 단계

상세 기술 항목은 [예측 시스템 통합 계획](PREDICTION_INTEGRATION_PLAN.md)을 따른다.

### 7.1 준비 조건

- 평타·런지·대시·적 공격이 모두 `SimStep.Run`으로 실행됨
- 플레이어 HP와 생존 상태 존재
- 적 HP·스턴·공격 상태 존재
- 정적 Navigation 또는 경로 캐시 존재
- 스냅샷 반복 할당 제거
- WorldHash에 모든 미래 영향 상태 포함
- 180틱 반복 결정론 테스트 통과

### 7.2 초기 탐색

```text
예측 길이: 3초
매크로: 15틱
Beam: 12
행동 후보 평균: 4개 이하
적: 4~8마리
후보: 1개
시간 제한: 200ms
```

행동 후보:

```text
전진
좌우 이동
후퇴
대기
4방향 대시
평타
런지(targetId)
```

### 7.3 평가

- 플레이어 생존
- 남은 HP
- 누적 피격 수
- 최소 안전 거리
- 포위 정도
- 남은 대시
- 런지·공격 쿨타임
- 처치 수
- 종료 위치의 탈출 가능성

### 7.4 후보 정밀 재검증

Beam Search가 뽑은 상위 후보를 초기 스냅샷에서 60Hz로 다시 실행한다.

- 매 틱 `PredictedFrame`
- 6틱마다 경로선
- 30틱마다 잔상
- 실제 행동 틱에 액션 이벤트
- 충돌 또는 사망 시 후보 폐기

## 8. 재생과 리듬 시스템

### 8.1 예측 리듬 실행과 상태 궤적 적용 방식

ADR-0003에 따라 저장한 `SimWorld` 전체 상태 궤적을 적용한다.

- 플레이어와 적 상태를 함께 적용한다.
- 플레이어만 저장 상태로 움직이고 적만 다시 시뮬레이션하는 혼합 방식은 금지한다.
- Miss 틱까지 적용된 상태를 실제 월드로 채택하고 일반 조작으로 복귀한다.
- 같은 스냅샷에서 같은 궤적을 생성하는지는 WorldHash 반복 테스트로 검증한다.

### 8.2 액션 이벤트

```csharp
public enum PredictedActionType
{
    Jump,
    DashForward,
    DashBackward,
    DashLeft,
    DashRight,
    Attack,
    Lunge
}
```

각 이벤트에는 다음을 저장한다.

- 발생 tick
- 행동 종류
- 타깃 ID
- Perfect 허용 범위
- Good 허용 범위

### 8.3 판정

| 결과 | 처리 |
| --- | --- |
| Perfect | 계획 행동 실행, 강한 연출 |
| Good | 계획 행동 실행, 약한 연출 |
| Miss | 해당 행동 실패, 예측 리듬 실행 종료 |

Miss 시 예상 위치로 보정하지 않고 현재 채택된 실제 상태에서 조작권을 반환한다.

## 9. 디자인 투입 순서

### D0. 기능용 도형

시점: 프로젝트 시작부터 전투·예측 코어 완성 전까지

- Cube 아레나

목적:

- 기능 검증
- 거리·속도·충돌 규격 확정
- 예측 가독성 검증

### D1. 시각 언어 확정

시점: 기본 전투가 완주된 직후

정할 것:

- 플레이어와 적 실루엣
- 아군·적·예측 잔상 색
- 공격 상태별 색
- 런지 가능 타깃 표시
- 예지 모드 화면 톤
- 액션 아이콘 기본 형태

이 단계에서도 최종 모델은 필요 없다. 색과 실루엣만으로 정보를 구분할 수 있어야 한다.

### D2. 임시 모델 교체

시점: 그레이박스 전투와 예측 후보 1개가 작동한 뒤

- Capsule 대신 Synty 또는 임시 캐릭터
- `VisualRoot` 아래 모델 배치
- 기존 `CollisionProxy` 유지
- 런지·평타·피격·사망 임시 애니메이션 연결
- 모델 스케일과 캡슐 정렬

프리팹 구조:

```text
EntityRoot
├─ CollisionProxy
├─ VisualRoot
│  └─ CharacterModel
├─ TargetIndicator
├─ AttackIndicator
└─ DebugView
```

논리 위치는 `EntityRoot`, 시각 보정은 `VisualRoot`에서 처리한다.

### D3. 아레나 디자인 교체

시점: Navigation Graph와 Drop Link가 고정된 뒤

순서:

1. 그레이박스 지형을 잠금
2. Navigation Node와 Link 백업
3. 그레이박스 위에 환경 메시 배치
4. 단순 프록시 Collider 유지
5. 메시가 통로나 시야를 가리지 않는지 검사
6. 런지 LOS와 도착점 재검증
7. Drop Link와 계단 경로 재검증

금지:

- 환경 모델 때문에 통로 폭 변경
- 모델에 맞춰 NavNode를 임의 이동
- 복잡한 MeshCollider를 게임 판정에 바로 사용
- 예측 검증 없이 충돌체 교체

### D4. 최종 캐릭터와 애니메이션

시점: 예측 → 선택 → 예측 리듬 실행 → Miss 전체 루프 통과 후

연결할 상태:

- Idle / Move
- Jump / Fall / Land
- Dash 4방향
- Attack Windup / Active / Recovery
- Lunge Windup / Travel / Hit / Recovery
- Enemy Attack Windup / Active / Recovery
- Stun / Death

Animator는 Sim 상태를 표현만 한다. Animation Event가 피해 판정이나 이동 완료를 결정하지 않는다.

### D5. 예지 전용 디자인

시점: 최종 후보 데이터가 안정된 뒤

- 시간 정지 색보정
- 3인칭 카메라 전환
- 반투명 잔상
- 경로선
- 액션 아이콘
- 선택 후보 강조
- 런지 타깃 연결선
- 다음 잔상 우선 강조

잔상은 처음에 캡슐 또는 단일 메시로 완성한 뒤, 일정이 남으면 캐릭터 실루엣으로 교체한다.

### D6. VFX·사운드·타격감

시점: 전투 규칙과 타이밍이 고정된 뒤

우선순위:

1. 적 Windup 텔레그래프
2. 평타 타격 피드백
3. 런지 시작·도착 피드백
4. 대시 방향 피드백
5. 예지 발동 사운드
6. Perfect/Good/Miss 피드백
7. 처치 연출
8. 환경 라이팅

VFX는 판정 틱을 따라가며, 판정을 결정하지 않는다.

### D7. UI 마감

시점: 후보 카드에 필요한 실제 데이터가 확정된 뒤

표시:

- 예지 게이지
- 대시 쿨타임
- 런지 쿨타임
- 플레이어 HP
- 후보 처치 수
- 예상 피격 수

- 액션 타이밍

데이터가 없는 임시 UI를 먼저 디자인하지 않는다.

## 15. 디자인 변경 시 회귀 방지 규칙

디자인 교체 PR에는 다음 확인이 필요하다.

- Collider 크기가 바뀌지 않았는가?
- `EntityRoot` 위치가 바뀌지 않았는가?
- `VisualRoot` 안에서만 보정했는가?
- NavNode·Drop Link가 이동하지 않았는가?
- 런지 LOS가 환경 장식에 막히지 않는가?
- Animator가 논리 상태를 변경하지 않는가?
- 새 VFX Collider가 게임 레이어에 들어가지 않았는가?
- 월드 해시 반복 테스트가 여전히 통과하는가?

디자인은 논리를 표현하며, 논리를 암묵적으로 변경하지 않는다.
