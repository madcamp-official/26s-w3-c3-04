# 보스(빛나는 구 코어) — 추적 레이저 보스 설계

> 상태: **Phase 0~2 구현·검증 완료(2026-07-23).** 런타임 확인: 보스 소환 → Chase→Windup→Fire 순환, 빔이
>   플레이어 추적·렌더, 지형이 시야 막으면 발사 안 함, 무적시간이 빔 피해를 ~45틱당 1로 조절(hp 3→0 확인).
> 소환: 개발 콘솔 **`spawn boss`** 또는 **`solo boss`**(전부 지우고 보스만). 보스는 지금 무적/스크립트.
> 작성 근거: 실제 코드 확인(EnemySim/EnemyBrain/CombatResolve/WorldHash 등). 파일·필드·상수명은 전부 실제와 대조했다.

---

## 0. 컨셉 요약

- **형태**: 빛나는 구(球) 코어. 공중에 부유. 사람형 몹과 완전히 다른 종.
- **행동(패턴 하나뿐)**: 플레이어를 어느 정도 빠르게 부유 추격 → **차지(텔레그래프)** → **굵고 빛나는 레이저를 n초간 발사**. 레이저는 **플레이어를 각속도 상한으로 추적**하고 **지형에 가로막힌다**. 플레이어는 엄폐물에 숨거나 옆으로 계속 이동해 회피.
- **이번 범위**: 보스는 **무적/스크립트**(피격·죽음 배선 없음, 연출·패턴만). 등장은 **개발 콘솔 소환**.
- **부수 기능**: **전역 무적시간(i-frame)** 을 정식 추가한다(빔이 연속이라 필수이고, 게임 전체에 올바른 기능).

### 확정된 결정(사용자 답변)
| 항목 | 결정 |
|---|---|
| 발사 중 오브 이동 | **제자리 고정**(빔만 회전 추적) |
| 빔 피해 방식 | **일반몹처럼 피해 1 + 무적시간** → 전역 i-frame 추가 |
| 보스 체력·처치 | **지금은 무적/스크립트**(연출만) |
| 등장 | **개발 콘솔 소환** |

### 이 설계에서 정한 기본값(전부 튜닝 대상, 이유 명시)
아래 "상수 표" 참조. 핵심 다이얼은 **`BossBeamTurnRate`(빔 추적 각속도)** 와 **`PlayerInvulnTicks`(무적 길이)**.

## Phase 0 — 전역 무적시간(i-frame)

빔은 매 틱 히트를 큐잉하는데, 현재 [CombatResolve.cs](../../PrecogPrototype/Assets/_Project/Sim/Combat/CombatResolve.cs) L96~103은 **큐의 모든 히트를 그대로 HP에서 깐다**(무적 판정 없음). 그대로면 60히트/초 = 즉사. 그래서 무적시간을 넣는다. 전역이라 **모든 적 피해에 일관 적용**된다.

### 0-1. `PlayerCombatState`에 필드 추가
[PlayerCombatState.cs](../../PrecogPrototype/Assets/_Project/Sim/Combat/PlayerCombatState.cs) — combat 소유, 공유 파일 아님.

```csharp
public int invulnTicks;     // ★추가: >0이면 피격 무적(들어오는 히트 무시). 매 틱 감소.
```
- 스냅샷: [Snapshot.cs](../../PrecogPrototype/Assets/_Project/Sim/Core/Snapshot.cs) L51 `dst.player = src.player`가 struct 통값 복사 → **자동으로 따라온다(수정 불필요).**

### 0-2. 상수

### 0-3. CombatResolve 수정
[CombatResolve.cs](../../PrecogPrototype/Assets/_Project/Sim/Combat/CombatResolve.cs) `Run()` 내부.

**(a) 타이머 감소** — 적 stun/bind 감소 루프(L27~31) 다음에 한 줄:
```csharp
ref PlayerCombatState pc = ref w.player.combat;
if (pc.invulnTicks > 0) pc.invulnTicks--;   // ★ 무적 타이머 감소(틱당 1회)
```
> 위치 주의: `pc`는 지금 L33에서 잡는다. 감소를 그 직후에 두면 됨. 아래 히트 적용 루프보다 **먼저** 감소해야 "이번 틱 피격 → 다음 틱부터 카운트다운"이 성립.

**(b) 히트 적용 루프 교체** (L96~103):
```csharp
for (int k = 0; k < w.pendingHitCount; k++)
{
    if (pc.gloryPhase != CombatConfig.GlNone) break;   // 글로리킬 중 무적(기존)
    if (pc.invulnTicks > 0) continue;                  // ★ 무적: 이 히트 무시(HP 안 깎음)
    pc.hp -= w.pendingHits[k].dmg;
    if (pc.hp < 0) pc.hp = 0;
    pc.hitStunTicks = CombatConfig.PlayerHitStunTicks;
    pc.invulnTicks  = CombatConfig.PlayerInvulnTicks;  // ★ 피격 순간 무적 시작 → 같은 틱 나머지 히트 + 이후 N틱 무시
}
w.pendingHitCount = 0;
```
- 같은 틱에 여러 히트가 큐에 있어도 **첫 히트가 무적을 켜므로 나머지는 continue로 무시**된다(여러 몹 동시타 → 1대만).

### 0-4. 해시
[CombatHash.cs](../../PrecogPrototype/Assets/_Project/Sim/Combat/CombatHash.cs) `MixPlayer` — `hitStunTicks` 줄(L37) 옆에:


### 0-5. Phase 0 부수효과(정직하게)
전역이라 **기존 적도 바뀐다**: 여러 몹 동시타가 1대로, 피격 직후 잠깐 무적이라 연타가 물러진다. 의도된 변화. 조절은 `PlayerInvulnTicks` 하나로. (원래 `PlayerHitStunTicks=0`이라 무적과 별개로 경직은 지금 없음 — 그대로 둔다.)

### 1-3. `EnemyBrain`에 분기 + StepBoss
[EnemyAI.cs](../../PrecogPrototype/Assets/_Project/Sim/AI/EnemyAI.cs) `EnemyBrain.Step()` — Flying 분기(L111) 다음에:

> 진입 전 상단 가드(launchTicks / traversalPhase / glory)는 그대로 통과: AddBoss로 낸 보스는 launchTicks=0·traversalPhase=None이라 이 분기까지 온다.

**StepBoss 의사코드** (EnemyBrain 안에 private static 추가):
```
static void StepBoss(ref SimWorld w, int i, in SimServices svc, float dt):
    ref e = w.enemies[i]; ref ai = e.ai
    Vector3 emitter = e.pos + Vector3.up * AIConfig.BossEmitterHeight   // 오브 코어 발사점
    Vector3 target  = w.player.pos + Vector3.up * AIConfig.PlayerTorso
    Vector3 toP = w.player.pos - e.pos; toP.y = 0
    float hd = toP.magnitude
    Vector3 faceH = hd > 1e-4 ? toP/hd : Forward(e.yaw)
    e.yaw = Atan2(faceH.x, faceH.z) * Rad2Deg           // 항상 플레이어 응시(텔레그래프)
    bool los = HasLOS(in e, in w.player, in svc)
    float hoverY = w.player.pos.y + AIConfig.BossHoverOffset

    switch ai.state:
      // ── 접근(부유). 선호 밴드 유지 + 시야 확보 ──
      default: // Chase 및 초기
        Vector3 wish = 0
        if (hd < AIConfig.BossBandMin)                 wish = -faceH   // 너무 가까움 → 후퇴
        else if (hd > AIConfig.BossBandMax || !los)    wish =  faceH   // 멀거나 시야 없음 → 접근
        BossHover(ref e, wish, hoverY, sepScratch[i], in svc, dt)      // FlyMove 재사용(아래 참고)
        if (hd <= SimConfig.EnemyAggroRange && hd >= AIConfig.BossBandMin
            && hd <= AIConfig.BossBandMax && los):
            ai.state = Windup; ai.stateTicks = 0
            ai.beamDir = (target - emitter).normalized                // 조준 초기화
        return

      // ── 차지(텔레그래프). 제자리 호버 + 빔 살짝 예비 추적 ──
      case Windup:
        ai.stateTicks++
        BossHover(ref e, Vector3.zero, hoverY, Vector3.zero, in svc, dt)   // 제자리(호버 높이만 유지)
        ai.beamDir = RotateTowards(ai.beamDir, (target-emitter).normalized,
                                   AIConfig.BossChargeTurnRate * dt)        // 차지 중 완만 추적(조준 맞춰둠)
        if (ai.stateTicks >= AIConfig.BossChargeTicks): ai.state = Fire; ai.stateTicks = 0
        return

      // ── 발사(n초). 제자리 고정, 빔만 각속도 상한으로 추적 ──
      case Fire:
        ai.stateTicks++
        BossHover(ref e, Vector3.zero, hoverY, Vector3.zero, in svc, dt)   // 제자리 고정
        // 빔 회전(각속도 상한) — 이게 회피의 핵심
        ai.beamDir = RotateTowards(ai.beamDir, (target-emitter).normalized,
                                   AIConfig.BossBeamTurnRate * dt)
        // 끝점·지형 가림
        var hit = svc.Collision.Raycast(emitter, ai.beamDir, AIConfig.BossBeamRange)
        float beamLen = hit.hit ? hit.distance : AIConfig.BossBeamRange
        // 플레이어 명중 판정(선분 근접 + 벽 뒤 아님)
        if (BeamHitsPlayer(emitter, ai.beamDir, beamLen, target,
                           AIConfig.BossBeamRadius + SimConfig.PlayerRadius)):
            w.QueuePlayerHit(ai.beamDir, AIConfig.BossBeamDamage)   // i-frame이 0.75초당 1로 조절
        if (ai.stateTicks >= AIConfig.BossFireTicks): ai.state = Recovery; ai.stateTicks = 0
        return

      // ── 쿨 ──
      case Recovery:
        ai.stateTicks++
        BossHover(ref e, Vector3.zero, hoverY, Vector3.zero, in svc, dt)
        if (ai.stateTicks >= AIConfig.BossRecoverTicks): ai.state = Chase; ai.stateTicks = 0
        return
```

**RotateTowards** (결정론 — `UnityEngine.Vector3.RotateTowards`는 순수 수학):
```csharp
static Vector3 RotateTowards(Vector3 cur, Vector3 want, float maxRadians)
    => Vector3.RotateTowards(cur, want, maxRadians, 0f).normalized;
// maxRadians = deg/s × dt × Deg2Rad. AIConfig에 deg/s로 두고 여기서 환산.
```
> 주의: 상수는 **도/초**로 두고 `AIConfig.BossBeamTurnRate * dt * Mathf.Deg2Rad`로 넘긴다. 위 의사코드의 `* dt`는 그 축약.

**BeamHitsPlayer** (선분 vs 점, 지형가림 내장 — 결정론):
```csharp
static bool BeamHitsPlayer(Vector3 origin, Vector3 dir, float len, Vector3 target, float radius)
{
    float t = Vector3.Dot(target - origin, dir);   // dir 정규화 전제
    if (t < 0f || t > len) return false;           // 발사점 뒤 또는 '빔 끝(=벽)보다 멀다'→가로막힘
    Vector3 closest = origin + dir * t;
    return (target - closest).sqrMagnitude <= radius * radius;
}
```
> **지형 가림이 이 한 판정으로 성립**: 벽이 빔을 `len`에서 끊으면, 벽 뒤 플레이어는 투영거리 `t > len` → false. 별도 LOS 레이 불필요(이미 `beamLen`에 반영됨).

**BossHover** — 부유 이동. **Phase 1은 기존 [FlyMove](../../PrecogPrototype/Assets/_Project/Sim/AI/EnemyAI.cs) 재사용**(EnemyBrain 내부 private이라 그대로 호출 가능):
```csharp
static void BossHover(ref EnemySim e, Vector3 wish, float targetY, Vector3 sep, in SimServices svc, float dt)
    => FlyMove(ref e, wish, targetY, sep, in svc, dt);
```
- 속도는 지금 `AIConfig.FlySpeed`(3.5)/관성 상수를 탄다. "어느 정도 빠르게"가 부족하면 **전용 상수(`BossHoverSpeed`)로 분리**하거나 FlyMove에 속도 인자를 추가(튜닝 단계에서). Phase 1은 재사용으로 동작 확보.

### 1-6. 스폰 경로 — 기존 종류 시스템에 `boss`만 추가 (전용 명령 불필요)

콘솔 `spawn <종류>`/`solo <종류>`는 이미 **`TryType(이름 → MobKind)` → `MapSpawnConfig.Axes(MobKind → c,m,s)` → `main.DevSpawn(c,m,s)` → `world.AddEnemy(at, c,m,s)`** 로 흐른다([DevConsole.cs](../../PrecogPrototype/Assets/_Project/View/Debug/DevConsole.cs) L218·L1327, [Main.cs](../../PrecogPrototype/Assets/_Project/View/Bootstrap/Main.cs) L425, [MapSpawnConfig.cs](../../PrecogPrototype/Assets/_Project/View/Spawn/MapSpawnConfig.cs)).
→ **종류 이름 `boss`만 등록하면 `spawn boss`/`solo boss`가 그대로 동작한다.** `AddBoss`·`SpawnBoss`·전용 콘솔 case 전부 **불필요**.

- (선택) `KindColor`에 보스색 한 줄, DevConsole `help`의 "종류:" 줄에 `boss` 표기.

- `LoadPrefabsOnce`에 `bossPrefab = Resources.Load<GameObject>("Enemies/BossOrb");` 추가, `ReplaceView` switch에 `case ViewKind.Orb`(없으면 Capsule 폴백), `IsBiped`엔 **미포함**(구체라 본 없음).
- 배치: Flying처럼 취급 — `ep + Vector3.up * (오브 반경)` 또는 그냥 `ep`(sim이 이미 호버 높이로 e.pos.y를 올려둠). 스케일은 `e.height * BossVisualMul`.

### 2-2. 오브 프리팹(에셋)
- `Resources/Enemies/BossOrb.prefab`: 발광 구(球). HDR emissive 재질(URP Bloom로 빛남). 자족적 재질(전역 렌더 설정 안 건드림 — 메모리 규칙 [[no-global-render-settings]]).
- 차지 중(Windup) 밝기/펄스 강화, 평상시(Chase) 은은하게. 상태는 `e.ai.state`로 판별.

### 2-3. 빔 VFX — `BossView` 컴포넌트(신규)
- 오브 뷰에 붙는 MonoBehaviour. 매 프레임 sim에서 `state`, `emitter=e.pos(+up*BossEmitterHeight)`, `beamDir` 읽음(EntityViews.Sync가 넘겨줌).
- **빔 렌더**: 자식 `LineRenderer`(또는 늘린 emissive 실린더). `state==Fire`일 때만 켬.
  - 끝점 = **View가 재레이캐스트**: `Physics.Raycast(emitter, beamDir, out hit, BossBeamRange, DefaultRaycastLayers, Ignore)` → 맞으면 `hit.point`, 아니면 `emitter+beamDir*BossBeamRange`. **sim의 가림 판정과 동일 마스크**라 시각·판정이 일치.
  - 굵고 빛남: LineRenderer width ≈ `BossBeamRadius*2`, HDR emissive 색 + Bloom. 끝에 임팩트 스파크(선택).
- **차지 텔레그래프**: `state==Windup`일 때 오브→예상 방향으로 가느다란 조준선/수렴 파티클(맞을 곳 경고). `beamDir`로 방향 표시.
- sim 상태만 읽으므로 **결정론·예지 무영향**. (예지 오버레이가 빔을 미리 보여주려면 별도 작업 — 이번 범위 밖.)

### 2-4. 빔 색/블룸
- HDR emissive(예: 강한 청백/적색) + URP Bloom. 기존 발광 재질(카타나 글로우 등) 방식 참고하되 자족 재질로. 뷰모델/전역 설정 안 건드림.

## 테스트 계획
1. **결정론(헤드리스)**: 보스 소환 + 고정 입력열로 N틱 두 번 굴려 `WorldHash.Compute` 동일 확인(기존 이중재생 하네스 재사용). 빔 발사·추적·가림 포함.

## 미확정·가정(복귀 후 확인)
- 빔 **추적 각속도**(`BossBeamTurnRate` 55도/s)와 **차지/발사/쿨 길이**는 첫 튜닝값. 플레이 느낌으로 조정.
