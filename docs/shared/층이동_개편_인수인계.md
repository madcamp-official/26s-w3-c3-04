# 층이동(traversal) 개편 — 예측 담당자 인수인계

작성일: 2026-07-20
작성: KJH 세션 (게임/Sim 측)
관련: `층이동_개편_설계.md`(설계·실측), `PREDICTION_CONTRACT.md`, `TRAVERSAL_MIGRATION.md`(구버전), ADR-0004

> **이 문서의 목적**: 층이동을 전면 개편하면서 **Sim 자료구조·동작·해시**가 바뀌었다.
> 예측(포크·재생·결정론)에 직접 영향을 주는 항목을 먼저 정리하고, 그 뒤에 전체 변경을 남긴다.

---

# 0. 30초 요약

- 층 전환의 권위가 **기하 자동판정 → 씬에 손으로 배치하는 마커(`TraversalLink`)** 로 바뀌었다.
- 공중 이동이 **선형보간 + 대칭 사인 + 고정 30틱 → 정점 보장 탄도(중력 적분, 닫힌 형식)** 로 바뀌었다.
- **`EnemySim`·`PlayerSim`에 필드가 늘었고 `WorldHash`가 바뀌었다.**
- **`EnemyMovement.Step` 시그니처가 바뀌었다.**
- **적 추적 목표가 `player.pos` → `player.lastGroundedPos`** 로 바뀌었다.
- **그래프 링크 비용 계산이 바뀌어 Floyd-Warshall 결과가 달라진다.**
- ADR-0004를 개정해 **스폰 시 개체 고정 상수**를 허용했다(판단 시 난수는 여전히 금지).
- ⚠️ **미완**: 마커가 아직 **예측 그래프에는 안 들어간다**(§7.1). NavMesh(평상시)에만 반영됨.

# 1. ⚠️ 예측에 직접 영향을 주는 변경 (최우선)

| # | 변경 | 예측 측 영향 | 조치 |
|---|---|---|---|
| 1 | **`WorldHash.Compute` 변경** | 기존에 기록해 둔 **골든 해시·기준값이 전부 무효** | 재기록 필요 |

| 4 | **`EnemyMovement.Step` 시그니처 변경** | 예측 코드가 직접 부르면 **컴파일 에러** | 호출부 수정 |
| 5 | **추적 목표 = `lastGroundedPos`** | 플레이어가 공중일 때 적 행동이 달라짐(예측도 동일하게 바뀜) | 인지 |

| 9 | **`ArenaNavLink`에 필드 6개 추가** | 베이크 데이터 스키마 변경 | 직렬화 확인 |

`NavMeshPathfinder`는 평상시 전용이고, 예측·following은 여전히 `GraphPathfinder`를 쓴다.

# 3. Sim 자료구조 변경 (필드 단위)

## 3.1 `EnemySim` (Sim/Core/EnemySim.cs)

```csharp

public int   traversalPauseTicks;    // 이번 도약의 주저 틱(시작 시 링크에서 복사)
```

  ```csharp

  ```
- ⚠️ `traversalPauseTicks`/`traversalRecoverTicks`를 별도 필드로 둔 이유:
  이전에 `descentTicks`/`repathTicks`를 재사용했다가 **의미가 충돌**해서 분리했다.

# 4. 동작 변경

## 4.1 `EnemyMovement` (전면 재작성)

**시그니처 변경 (⚠️ 호출부 수정 필요)**
```csharp
// 전
public static void Step(ref EnemySim e, in PlayerSim player, Vector3 sep, in SimServices svc, float dt)
// 후
public static void Step(ref SimWorld w, int selfIndex, Vector3 sep, in SimServices svc, float dt)
```
슬롯 점유를 판정하려면 **다른 적들을 봐야 해서** 월드 전체가 필요하다.

**추적 목표**
```csharp
public static Vector3 ChaseTarget(in PlayerSim p) => p.grounded ? p.pos : p.lastGroundedPos;
```

**도약 실행 (Pause → Airborne → Recovery)**
- `Pause`: 주저 틱. **0이면 단계 자체를 건너뛴다**(0 = 완전히 없음).
- `Airborne`: **닫힌 형식**으로 매 틱 위치를 직접 계산 — 누적 적분이 아니라 포크 재현이 보장된다.
  ```csharp
  arc = TraversalBallistics.Solve(e.jumpStart, e.jumpEnd, e.traversalClearance, e.traversalGravity);
  arc.flightTicks = e.jumpDuration;   // 시작 시 확정한 틱 유지
  e.pos = arc.At(e.traversalTicks);
  ```
- `Recovery`: 멈칫 틱. 0이면 착지 즉시 종료.

**슬롯 점유·정원 대기**
- **별도 자료구조 없음.** `activeTraversalLinkId` + `traversalSlot`을 들고,
  적 배열을 훑어 "이 링크를 쓰는 적 수 / 점유된 슬롯"을 센다 → 포크 시 자동 복사.
- 정원 초과 또는 빈 슬롯 없음 → 발판에서 **대기**(제자리 정지). 순서는 **배열 인덱스 순 = 결정론적**.

**착지 지점 검증** (도약 시작 시 1회)
```csharp
// 슬롯 오프셋 자리에 바닥이 있고 캡슐이 들어가는지 확인, 아니면 정확한 착지점으로 폴백
svc.Collision.SampleGround(...) && svc.Collision.CanOccupyCapsule(...)
```
⚠️ **충돌 질의 2회가 도약 시작 시 발생**한다(매 틱 아님). NavMesh 아님 → 계약 위반 아님.

## 4.2 `EnemyAI`

```csharp
// gloryStage 체크 직후에 추가
if (e.traversalPhase != TraversalPhase.None)
{ EnemyMovement.Step(ref w, i, Vector3.zero, in svc, dt); return; }
```
**도약 중엔 상태머신이 끼어들지 못한다.** 안 막으면 공중에서 공격 시퀀스로 전환해
`Plant`/`RangedMove`가 위치를 덮어써 궤적이 끊긴다. **도약은 시작하면 착지까지 커밋.**

호출부 2곳이 새 시그니처로 변경됨.

## 4.3 `SimStep`

```csharp
// ClampToNavMesh 제외 조건에 추가
if (e.traversalPhase != TraversalPhase.None) continue;
```
⚠️ **이게 없으면 매 틱 공중 좌표의 XZ를 걷기면으로 되당겨 탄도와 싸운다**(궤적이 뚝뚝 끊김).
구식 `descentPhase`만 제외하고 있어서 생긴 문제였다.

`Separate`(겹침 밀치기)는 이미 `TraversalPhase.Airborne`을 제외하고 있었다 — 변경 없음.

## 4.4 `GraphPathfinder` (예측 경로 — 중요)

**간선 비용**
```csharp
// 전: 순수 직선거리
// 후:
float costMeters = l.costDistance > 0f ? l.costDistance
                                       : Vector3.Distance(ns[a].position, ns[b].position);
int cost = Mathf.Max(1, Mathf.RoundToInt(costMeters * 100f));
```
**왜**: 도약은 주저+비행+멈칫 때문에 실제로 오래 걸리는데 직선거리로 계산하면 **공짜로 보인다.**
평상시(NavMesh)는 보정된 비용을 쓰므로, 그래프만 안 고치면 **예측은 "뛰어내린다"고 하는데
실제로는 경사로로 돌아오는** 괴리가 난다. → **Floyd-Warshall 결과가 달라진다.**

**`NextStep`이 탄도 파라미터를 실어 보냄** (`clearance/gravity/pauseTicks/recoverTicks/slotCount/slotSpread`).

## 4.5 `NavMeshPathfinder` (평상시 전용)

- **`DropDetect` 기하 자동판정 폐기** — 층 전환은 전부 명시 마커.
- **몹별 areaMask**: `agentMask`에서 유도. Traversal이 아니면 `LeapTraversal` Area 배제.
- **마커 진입 판정**: 경로 코너 좌표를 마커 출발점과 대조.
  - 연속 중복 코너 병합(출발점과 링크 시작점이 겹치면 좌표가 두 번 나옴)
  - "이미 발판 위에 서 있음" 판정 별도(발판에 서면 다음 코너가 착지점으로 바뀜)

# 5. 결정론 관련 정리

| 항목 | 결정론 안전한가 | 근거 |
|---|---|---|
| 탄도 궤적 | ✅ | **닫힌 형식**(`start + v·t + ½gt²`), 고정 dt. 누적 적분 아님 |
| 주저·멈칫 틱 | ✅ | 링크에 구워진 값을 상태로 복사 |
| 슬롯 점유·대기 | ✅ | 월드 상태(적 배열)만 읽음, 순회 순서 고정 |
| 개성값 | ✅ | `Hash(id)` 순수 함수, 상태 없음 |
| `lastGroundedPos` | ✅ | 월드 상태, 해시 포함 |
| 착지 검증 | ✅ | 충돌 질의(결정론적), 도약 시작 시 1회 |
| NavMesh 사용 | ✅ | **예측 경로에서 호출 없음** (§8.3 유지) |
| `SimConfig` static 6개 | ⚠️ | **예측 중 변경 금지** |

# 7. ⚠️ 미완·주의 사항 (반드시 읽을 것)

## 7.1 마커가 아직 예측 그래프에 안 들어간다 (가장 큰 미완)

`Main.Start` 현재 상태:
```csharp
var baked = TraversalBaker.Bake(markers, System.Array.Empty<ArenaNavNode>());
navPathfinder.links = baked.ToArray();          // ← NavMesh(평상시)에만 반영
graphPathfinder = GraphPathfinder.CreateArena(); // ← 예측은 여전히 하드코딩 아레나
```
- 베이크에 **빈 노드 배열**을 넘겨서 `fromNodeId/toNodeId = -1`이다.
- 즉 **예측은 마커 층이동을 아직 모른다.**
- 완성하려면: 그래프 노드 집합을 만들고(또는 마커 끝점을 노드로 승격) 링크의 노드 id를 채운 뒤
  `GraphPathfinder`를 그 베이크로 생성해야 한다. **여기가 다음 작업 지점이다.**

## 7.2 NavMesh Area 미생성
`Leap` / `LeapTraversal` Area가 프로젝트 Navigation 설정에 **아직 없다.**
없으면 `AreaIndex`가 0으로 폴백 → **몹별 게이팅이 무효**(전부 통과). 나머지는 정상 동작.

## 7.3 링크 폭은 반드시 0
`NavMeshLink.width > 0`이면 NavMesh가 진입점을 **변 위 아무 곳**에나 잡아
경로 코너가 링크 좌표와 최대 폭/2만큼 어긋난다(실측 0.50m). 그러면 진입 판정이 **간헐적으로 실패**한다.
→ Baker가 `width = 0`으로 굽는다. **바꾸지 말 것.**

## 7.4 검증 캡슐 크기
궤적 충돌 검증은 기본 **일반몹 크기**로 한다. 대형몹(3배, 높이 4.3m)으로 검증하면
실내처럼 층간이 낮은 맵에서 **거의 모든 링크가 무효**가 되어 층이동이 통째로 사라진다.
대형몹이 꼭 지나야 하는 링크만 마커의 `validateForLargeMobs`를 켠다.

## 7.5 마커 끝점은 NavMesh 안쪽에
NavMesh는 에이전트 반경(0.5m)만큼 가장자리가 깎여 있다. 발판 끝에 딱 붙여 찍으면 **면 밖**이 되어
링크가 연결되지 않는다. Baker가 `SamplePosition`으로 당기지만, **F2 시각화에서 끝점이 빨간색이면 옮겨야 한다.**

## 7.6 공중몹
공중몹(Flying)은 마커를 쓰지 않는다. 별도 3D 항법은 **이번 범위 밖**이다.

|---|---|

| `Tools/층이동 링크/NavMesh 시각화 켜기·끄기` | |
| **Play 중 `F1`** | 튜닝 패널(주저·멈칫 슬라이더, "전부 0" 버튼) |
| **Play 중 `F2`** | NavMesh 시각화 |

**Scene 뷰 조작**: 끝점 드래그 핸들 / 궤적 꼭대기(노란 구) 드래그 = clearance 수동 전환 /
인스펙터 "자동으로 되돌리기" / **▶ 고스트 재생**(주저→비행→멈칫을 실제 틱 길이로).

**색 규약**: 궤적 초록·파랑 = 정상, **빨강 = 무효**(Bake 제외). 슬롯 초록 = 사용 가능, 빨강 = 폐기.
NavMesh 시각화에서 마커 끝점 **빨강 = 면 밖**.
