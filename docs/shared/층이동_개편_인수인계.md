# 층이동(traversal) 개편 — 변경 내용

최종 갱신: 2026-07-20 · 대상 커밋 `425017b`
관련: `층이동_개편_설계.md`, `PREDICTION_CONTRACT.md`, ADR-0004

> 예측 담당자용. **무엇이 어떻게 바뀌었는지**만 적는다.

# 1. 한눈에

| 항목 | 이전 | 이후 |
|---|---|---|
| 층 전환 지점 | 낙차 기하 자동판정(`DropDetect`) | **씬에 배치한 마커**(`TraversalLink`) |
| 공중 이동 | 선형보간 + 대칭 사인 | **정점 보장 탄도**(중력 적분) |
| 비행 시간 | **고정 30틱** | **물리로 결정**(낙차에 따라 다름) |
| 속도 | 수평 등속 | **상승 초반 가속 / 하강 막판 가속** |
| 주저·멈칫 | 12틱 / 15틱 고정 | **링크 길이 비례** |
| 몹별 게이팅 | 평상시 불가(`agentMask` 무시) | **NavMesh Area + 그래프 agentMask** |
| 적 추적 목표 | `player.pos` | **`player.lastGroundedPos`** |
| 예측 그래프 | 코드 하드코딩(SampleScene 전용) | **맵별로 구운 에셋** + 없으면 폴백 |
| 도약 시 착지 | 착지점 1곳 | **착지 슬롯 + 링크 정원 대기** |
| 분리 스티어링 | 전 개체 동일 가중치 | **개체 고정 개성값으로 차등** |
| `NearestNode` | 전체 선형 스캔 | **격자 공간 색인**(24노드 이상) |

# 2. Sim 자료구조 — 추가된 필드

## `EnemySim` (+6)
```csharp
int   traversalSlot;          // 점유 슬롯(-1 = 없음)
int   traversalPauseTicks;    // 이번 도약의 주저
int   traversalRecoverTicks;  // 이번 도약의 멈칫
float traversalClearance;     // 이번 도약의 정점 여유
float traversalGravity;       // 이번 도약의 중력
float personality;            // 개체 고정 개성값 0~1
```
`Spawn()`에서 `traversalSlot = -1`, `personality = Personality(id)` 초기화.
`Personality`는 순수 해시(난수 스트림 아님).

## `PlayerSim` (+1)
```csharp
Vector3 lastGroundedPos;   // PlayerMovement.Step에서 접지할 때마다 갱신
```

## `PathStep` (+6)
```csharp
float clearance, gravity;
int   pauseTicks, recoverTicks;
int   slotCount; float slotSpread;
```

## `ArenaNavLink` (+6)
```csharp
Vector3 traversalStartPosition;
float   clearance, gravity;
int     pauseTicks, recoverTicks;
float   costDistance;
```
기존 `landingSlotCount` / `landingSpread`는 **선언만 있고 미사용이었는데 이제 실제로 쓰인다**.

## `WorldHash` — 믹스 추가
```csharp
MixV(w.player.lastGroundedPos);
// enemy, jumpEnd 다음
Mix (e.traversalSlot + 1); Mix (e.traversalPauseTicks); Mix (e.traversalRecoverTicks);
MixF(e.traversalClearance); MixF(e.traversalGravity);   MixF(e.personality);
```
→ **해시값이 바뀐다.**

# 3. API 변경

## `EnemyMovement.Step`
```csharp
// 전
Step(ref EnemySim e, in PlayerSim player, Vector3 sep, in SimServices svc, float dt)
// 후
Step(ref SimWorld w, int selfIndex, Vector3 sep, in SimServices svc, float dt)
```
슬롯 점유 판정에 다른 적들을 봐야 해서 월드 전체를 받는다.

## `EnemyMovement.ChaseTarget` (신규 public)
```csharp
Vector3 ChaseTarget(in PlayerSim p) => p.grounded ? p.pos : p.lastGroundedPos;
```

## `EnemySim.Personality` (신규 static)
```csharp
float Personality(int id)   // Knuth 승수 + xorshift 믹스 → 0~1
```

# 4. 동작 변경

## 4.1 도약 실행 (`EnemyMovement`)
- **전**: `Pause(12) → Airborne(30, Lerp + sin·1.25) → Recovery(15)`
- **후**: `Pause(길이비례) → Airborne(탄도, 물리로 결정) → Recovery(길이비례)`
  - 위치는 **닫힌 형식**으로 tick에서 직접 계산(누적 적분 아님)
  - 궤적은 `traversalClearance/Gravity`로 재구성 → 출발 시 계획한 아치 유지
  - **주저·멈칫이 0이면 그 단계를 건너뛴다**(전에는 최소 1틱 남았음)

## 4.2 착지 (신규)
- **전**: 전원이 링크의 착지점 한 곳에 꽂힘
- **후**: **슬롯 점유**(링 배치) + **링크 정원 초과 시 발판에서 대기**
  - 점유 상태는 별도 자료구조 없이 적 배열 훑기로 판정(`activeTraversalLinkId` + `traversalSlot`)
  - 도약 시작 시 **1회** `SampleGround` + `CanOccupyCapsule`로 슬롯 검증, 실패 시 착지점 폴백

## 4.3 `EnemyAI` (신규 가드)
```csharp
// gloryStage 체크 직후
if (e.traversalPhase != TraversalPhase.None)
{ EnemyMovement.Step(ref w, i, Vector3.zero, in svc, dt); return; }
```
도약 중엔 상태머신이 개입하지 않는다(전에는 공중에서 공격 전이로 위치가 덮였다).

## 4.4 `SimStep.ClampToNavMesh`
```csharp
// 제외 조건 추가
if (e.traversalPhase != TraversalPhase.None) continue;
```
전에는 `descentPhase`만 제외해서 도약 중 위치가 걷기면으로 되당겨졌다.
`Separate`는 이미 `Airborne`을 제외하고 있었다 — **변경 없음**.

## 4.5 `GraphPathfinder`
| | 이전 | 이후 |
|---|---|---|
| 간선 비용 | 직선거리 `× 100` | `costDistance` 있으면 그 값(환산거리) |
| `NearestNode` | 전체 선형 스캔 | **격자 색인**(24노드 이상), 동률 해소는 동일 |
| `NextStep` | kind·좌표만 | **탄도 파라미터·슬롯 정보 추가 전달** |
| 미지정 링크 | — | `clearance <= 0`이면 **길이 기반 기본값 자동 주입** |

→ 비용이 바뀌므로 **Floyd-Warshall 결과가 달라진다.**

## 4.6 `NavMeshPathfinder` (평상시 전용)
| | 이전 | 이후 |
|---|---|---|
| 층 전환 판정 | 낙차 기하(`DropDetect`) | **마커 좌표 매칭**(중복 코너 병합 + 발판 위 판정) |
| `agentMask` | **무시** | areaMask 유도 → Traversal 아니면 `LeapTraversal` 배제 |

## 4.7 분리 스티어링
- **전**: 전 개체가 `SeparationWeight` 동일
- **후**: `personality`가 세기를 `SeparationScaleMin ~ 1`배로 가름

# 5. 상수 변경

## 신규 (`SimConfig`)
```csharp
TraversalGravity 22 / MinClearance 0.6 / ClearanceRatio 0.18 / MaxClearance 4   (const)
TraversalSlotMax 6 / SlotGapMul 2.2 / LinkCapacity 2                            (const)
★ TraversalAscendShape 1.5 / TraversalDescendShape 1.9
★ TraversalPauseMin 3 / PauseMax 22 / RecoverMin 4 / RecoverMax 30
★ TraversalLengthRef 14 / TraversalLengthExp 1.9
```

## `const → static` 전환 (★ = 예측 중 변경 금지 대상 추가)
```csharp
SimConfig : Traversal(Ascend|Descend)Shape, Pause/Recover Min·Max, LengthRef, LengthExp   (8개)
AIConfig  : SeparationRadius, SeparationWeight, SeparationMaxPush, SeparationScaleMin      (4개)
```

## 사실상 폐기 (참조 제거됨)
```csharp
TraversalPauseTicks 12 / TraversalRecoveryTicks 15 / TraversalDefaultAirTicks 30 / TraversalArcHeight 1.25
DropDetectMinHeight / DropDetectRatio   ← NavMeshPathfinder가 더 이상 안 씀
```

# 7. 예측 그래프 (가장 큰 변화)

- **전**: `Main.Start`가 항상 `GraphPathfinder.CreateArena()` — SampleScene 좌표 하드코딩 17노드
- **후**: 씬 이름으로 **구운 에셋을 로드**, 없으면 `CreateArena()`로 **폴백**

```csharp
var asset = Resources.Load<PredictionGraphAsset>(PredictionGraphAsset.ResourceName(sceneName));
graphPathfinder = (asset != null && asset.HasData)
    ? GraphPathfinder.FromBake(asset.ToBake())
    : GraphPathfinder.CreateArena();
```

**SampleScene은 굽지 않으면 이전과 동일하게 동작한다.**
Arena_3 등 새 맵은 `Tools/층이동 링크/예측 그래프 굽기`(Play 중)로 구워야 예측이 의미를 갖는다.

굽기 결과에는 마커 링크가 **`agentMask`와 탄도 파라미터를 달고** 들어가므로,
예측에서도 **층이동과 몹별 제한이 그대로 적용**된다(이전에는 둘 다 없었다).

# 8. 예측 영향 정리

| 변경 | 결과 |
|---|---|
| `WorldHash` 구조 | **기록된 골든 해시 무효** |
| `EnemyMovement.Step` 시그니처 | 직접 호출부 **컴파일 에러** |
| 필드 추가(적 6 · 플레이어 1) | 수동 `CopyTo`가 있으면 누락 가능 |
| 추적 목표 변경 | 플레이어 공중일 때 적 행동이 달라짐 |
| 도약 궤적·소요 틱 변경 | 예측 결과가 이전과 달라지는 것이 정상 |
| 그래프 간선 비용 변경 | Floyd-Warshall 경로 변경 |
| static 12개 | 예측 중 변경 금지 대상 |
| 공간 색인 | **동작 동일**(동률 해소 유지, 테스트 64/64 통과) |
| NavMesh 호출 | **예측 경로에서 없음** — 계약 §8.3 유지 |

# 9. 팀원 조치

1. **골든 해시 재생성**
2. `EnemyMovement.Step` **직접 호출부** 시그니처 수정
3. `Snapshot.Clone`/`CopyTo`에 수동 복사가 있으면 신규 필드 7개 확인
4. **static 튜닝값 12개**를 "예측 중 변경 금지" 목록에 추가
5. SampleScene은 폴백으로 그대로 동작 — **굽지 않아도 됨**
