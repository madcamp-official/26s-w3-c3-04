# 층이동(traversal) 개편 — 전체 정리 · 예측 담당자 인수인계

최종 갱신: 2026-07-20
작성: KJH 세션 (게임/Sim 측)
관련 커밋: `9ab6111`(개편 본체) → `5d4b4bd`(충돌검증·고스트) → `890e2f3`(끊김·간헐실패 수정) → `3acaea5`(벽뚫림·가속연출·다양성)
관련 문서: `층이동_개편_설계.md`(설계·실측), `PREDICTION_CONTRACT.md`, ADR-0004

> **목적**: 층이동을 전면 개편하면서 Sim 자료구조·동작·해시가 바뀌었다.
> 예측(포크·재생·결정론)에 영향을 주는 항목을 먼저 정리하고, 그 뒤 전체 변경과 미완 사항을 남긴다.

---

# 0. 요약

- 층 전환 권위: **기하 자동판정 → 씬에 배치하는 마커(`TraversalLink`)**
- 공중 이동: **선형보간 + 대칭사인 + 고정 30틱 → 정점 보장 탄도(중력 적분, 닫힌 형식)**
- 도약에 **속도 배분 연출** 추가(상승은 초반 가속, 하강은 막판 가속)
- **`EnemySim`·`PlayerSim` 필드 증가, `WorldHash` 변경**
- **`EnemyMovement.Step` 시그니처 변경**
- 적 추적 목표: **`player.pos` → `player.lastGroundedPos`**
- 그래프 링크 비용이 **환산거리**로 바뀌어 Floyd-Warshall 결과가 달라짐
- ADR-0004 개정: **스폰 시 개체 고정 상수 허용**(판단 시 난수는 계속 금지)
- ⚠️ **미완**: 마커가 아직 **예측 그래프에 안 들어간다**(§8.1)

# 3. Sim 자료구조 (필드 단위)

## 3.1 `EnemySim`
```csharp
public int   traversalSlot;          // 점유 슬롯(-1 = 없음)
public int   traversalPauseTicks;    // 이번 도약의 주저
public int   traversalRecoverTicks;  // 이번 도약의 멈칫
public float traversalClearance;     // 이번 도약의 정점 여유 ← 궤적 재구성에 필수
public float traversalGravity;       // 이번 도약의 중력      ← 궤적 재구성에 필수
public float personality;            // 개체 고정 개성값 0~1(스폰 시 1회, 불변)
```
`Spawn()`이 `traversalSlot = -1`, `personality = Personality(id)` 초기화.
`Personality(int id)`는 **순수 해시**(난수 스트림 아님, 상태 없음) → 포크 안전.

> `traversalClearance/Gravity`를 안 들면 비행 중 다른 아치로 풀려 궤적이 끊긴다(실제 겪은 버그).

## 3.2 `PlayerSim`
```csharp
public Vector3 lastGroundedPos;   // 접지할 때마다 갱신(PlayerMovement.Step)
```
공중 좌표를 목표로 삼으면 `SamplePosition`(반경 4m) 실패 → `MoveKind.None` → **적 완전 정지** 버그가 있었다.
지면 투영(레이캐스트) 대신 이 방식인 이유는 **질의 비용 0**(337k 포크 유리).

## 3.3 `WorldHash` 추가분
```csharp
h = MixV(h, w.player.lastGroundedPos);
// enemy (jumpEnd 다음)
h = Mix (h, (ulong)(e.traversalSlot + 1));
h = Mix (h, (ulong)e.traversalPauseTicks);
h = Mix (h, (ulong)e.traversalRecoverTicks);
h = MixF(h, e.traversalClearance);
h = MixF(h, e.traversalGravity);
h = MixF(h, e.personality);
```

## 3.4 `PathStep` 추가분
```csharp
public float clearance, gravity;
public int   pauseTicks, recoverTicks;
public int   slotCount;      // 검증 통과 슬롯 수
public float slotSpread;     // 슬롯 링 반경
```
**값이 아니라 파라미터를 넘긴다** — 세 곳이 같은 함수로 궤적을 풀어 일치시키려는 의도.

## 3.5 `ArenaNavLink` 추가분
```csharp
public Vector3 traversalStartPosition;  // 도약 발판(코너 매칭용)
public float   clearance, gravity;
public int     pauseTicks, recoverTicks;
public float   costDistance;            // 길찾기 비용(환산거리)
```
기존 `landingSlotCount`/`landingSpread`가 **이제 실제로 쓰인다**(이전엔 선언만).

# 4. 동작 변경

## 4.1 `EnemyMovement` (전면 재작성)
```csharp
// 전: Step(ref EnemySim e, in PlayerSim player, Vector3 sep, in SimServices svc, float dt)
// 후: Step(ref SimWorld w, int selfIndex, Vector3 sep, in SimServices svc, float dt)
```
슬롯 점유 판정에 **다른 적들을 봐야 해서** 월드 전체가 필요하다.

- `ChaseTarget(in p) => p.grounded ? p.pos : p.lastGroundedPos`
- **Pause → Airborne → Recovery**. 주저 0이면 Pause 단계를 **건너뛴다**(0 = 완전히 없음).
- **Airborne**: 닫힌 형식으로 매 틱 위치 직접 계산(누적 적분 아님).
  ```csharp
  arc = TraversalBallistics.Solve(jumpStart, jumpEnd, traversalClearance, traversalGravity);
  arc.flightTicks = jumpDuration;      // 시작 시 확정한 틱 유지
  pos = arc.At(traversalTicks);
  ```
- **슬롯 점유·정원 대기**: 별도 자료구조 없이 적 배열을 훑어 판정
  (`activeTraversalLinkId` + `traversalSlot`) → 포크 시 자동 복사. 순서는 배열 인덱스 = 결정론적.
- **착지 검증**: 도약 시작 시 1회 `SampleGround` + `CanOccupyCapsule`.
  실패하면 정확한 착지점으로 폴백(허공 착지 → 발판으로 순간이동하던 버그 차단).
  ⚠️ 충돌 질의 2회 발생(매 틱 아님, NavMesh 아님 → 계약 위반 아님).

## 4.2 `EnemyAI`
```csharp
if (e.traversalPhase != TraversalPhase.None)
{ EnemyMovement.Step(ref w, i, Vector3.zero, in svc, dt); return; }
```
**도약 중엔 상태머신 진입 차단.** 안 막으면 공중에서 공격 시퀀스로 전환해
`Plant`/`RangedMove`가 위치를 덮어써 궤적이 끊긴다. **시작하면 착지까지 커밋.**

## 4.3 `SimStep`
```csharp
// ClampToNavMesh 제외 조건에 추가
if (e.traversalPhase != TraversalPhase.None) continue;
```
⚠️ 없으면 매 틱 공중 좌표의 XZ를 걷기면으로 되당겨 **탄도와 싸운다**(궤적이 뚝뚝 끊김).
`Separate`는 이미 `Airborne`을 제외하고 있었다(변경 없음).

## 4.4 `TraversalBallistics` — 속도 배분
궤적 **모양은 탄도 그대로**, 그 위를 지나는 **속도만** 바꾼다(시간 워핑).
```csharp
x = tick / flightTicks;                    // 정규화 진행도
u = ascend ? 1 - (1-x)^p : x^p;            // 상승 ease-out / 하강 ease-in
t = u * flightTicks * TickDelta;           // 이 t로 탄도식 평가
```
- 순수 물리는 아니지만 **의도한 연출**(둠식 느낌). 닫힌 형식이라 **결정론 유지**.
- 지수 2.2는 과했다 — 마지막 20% 시간에 경로의 3%만 진행해 끝에서 기어간다. **1.5/1.9로 완화**.

## 4.5 `GraphPathfinder` (예측 경로)
```csharp
float costMeters = l.costDistance > 0f ? l.costDistance : Vector3.Distance(...);
int cost = Mathf.Max(1, Mathf.RoundToInt(costMeters * 100f));
```
직선거리로 두면 **도약이 공짜로 보여**, 평상시(보정됨)와 정반대 판단을 한다
→ "예측은 뛰어내린다는데 실제로는 경사로로 돌아옴". `NextStep`이 탄도 파라미터도 실어 보낸다.

## 4.6 `NavMeshPathfinder` (평상시 전용)
- `DropDetect` 기하 자동판정 **폐기**
- **몹별 areaMask**: `agentMask`에서 유도. Traversal이 아니면 `LeapTraversal` Area 배제
- **마커 진입 판정**: 경로 코너 좌표를 마커 출발점과 대조
  - 연속 중복 코너 병합
  - "이미 발판 위에 서 있음" 별도 판정(발판에 서면 다음 코너가 착지점으로 바뀜)

# 7. 잡았던 버그 (재발 방지용 기록)

| 증상 | 원인 |
|---|---|
| 발판까지 가서 **부들부들**, 간헐적으로만 도약 | **NavMeshLink 폭 1m** → NavMesh가 진입점을 변 위 아무 곳에나 잡아 코너가 링크 좌표와 최대 0.5m 어긋남(실측 0.50m). 허용오차 0.35m라 **접근 각도에 따라 매칭 실패**. → **폭 0(점 링크)**, 실측 0.003m |
| 궤적이 **뚝뚝 끊김** | `ClampToNavMesh`가 도약 중인 몹까지 걷기면으로 되당김(구식 `descentPhase`만 제외) |
| 공중에서 **순간이동** | AI 상태머신이 공중 몹을 공격 시퀀스로 가로채 위치 덮어씀 |
| 궤적이 **계획과 다름** | 비행 중 재구성에 clearance를 0으로 넘겨 다른 아치로 풀림 |
| 착지 후 **발판으로 순간이동** | 슬롯 오프셋을 검증 없이 사용 → 허공 착지 |
| 실내 링크가 **전부 무효** | 검증 캡슐이 대형몹(4.3m)이라 층간 3m 실내에서 전부 막힘 |
| 링크 **미연결** | 마커 끝점이 NavMesh 밖(가장자리가 에이전트 반경만큼 카브됨) |
| 주저·멈칫 **0이 안 먹음** | `> 0`이면 기본값으로 되돌림 + 단계가 최소 1틱 남음 |
| 궤적이 **벽을 뚫음** | 점만 찍어 검사 → 점 사이 얇은 벽 통과. **구간 `CapsuleCast` 스윕**으로 교체 |
| 자동배치가 **비슷한 패턴만** | 중복 판정이 "양 끝이 둘 다 가까움"(AND)이라 한 발판의 부채꼴이 전부 통과 |

# 8. ⚠️ 미완·주의

## 8.1 마커가 아직 예측 그래프에 안 들어간다 (가장 큰 미완)
```csharp
// Main.Start 현재
var baked = TraversalBaker.Bake(markers, System.Array.Empty<ArenaNavNode>());
navPathfinder.links = baked.ToArray();           // ← NavMesh(평상시)에만
graphPathfinder = GraphPathfinder.CreateArena();  // ← 예측은 하드코딩 아레나
```
빈 노드 배열을 넘겨 `fromNodeId/toNodeId = -1`이다. **예측은 마커 층이동을 모른다.**
완성하려면 그래프 노드 집합을 만들고(또는 마커 끝점을 노드로 승격) 링크 노드 id를 채운 뒤
`GraphPathfinder`를 그 베이크로 생성해야 한다. **다음 작업 지점.**

## 8.2 NavMesh Area
`Leap` / `LeapTraversal` Area가 없으면 코드가 0(Walkable)으로 폴백 → **몹별 게이팅 무효**.
→ `Tools/층이동 링크/NavMesh Area 생성` 실행 후 **Play 재시작**(재베이크 필요).
링크 매칭 단계의 `agentMask` 검사는 살아 있어 도약 자체는 막히지만,
경로가 계속 그 링크로 안내해 **"시도하는 것처럼" 보인다.**

## 8.3 링크 폭은 반드시 0
`width > 0`이면 코너가 링크 좌표와 어긋나 진입 판정이 간헐 실패한다. **바꾸지 말 것.**

## 8.4 검증 캡슐 크기
기본 **일반몹**. 대형몹으로 검증하면 실내에서 거의 모든 링크가 무효가 된다.
대형몹이 꼭 지나야 하는 링크만 마커의 `validateForLargeMobs`를 켠다.

## 8.5 마커 끝점은 NavMesh 안쪽에
NavMesh는 에이전트 반경(0.5m)만큼 가장자리가 깎인다. Baker가 `SamplePosition`으로 당기지만,
**F2 시각화에서 끝점이 빨강이면 옮겨야 한다.**

## 8.6 공중몹
공중몹(Flying)은 마커를 쓰지 않는다. 별도 3D 항법은 **범위 밖**.

## 9.1 자동 배치 창
- **낙하형**(위→아래) + **간극형**(같은 높이인데 사이가 끊긴 곳) 둘 다 탐지
- **[분석]** 으로 개수만 먼저 확인 → Scene 뷰에 **초록 점(샘플된 면)** 과 후보 선이 표시됨
- 종류 분류: `층간 높이 × 배수`(기본 3.9 × 1.5 = 5.85m) 초과 → ② 상승제한
- ① 일반과 ② 상승제한을 **번갈아 선정**(안 그러면 큰 낙차가 자리를 다 먹음)
- **다양성**: 발판 단위로 묶어 개수 제한 + 방향 최소차 요구

| 증상 | 조절 |
|---|---|
| 다리·좁은 발판에 점이 없음 | 격자 간격 ↓ |
| 점은 있는데 링크 없음 | 최소 낙차 ↓ / 가장자리 낙차 ↓ / 틈 깊이 ↓ |
| 비슷한 패턴 반복 | 같은 발판 반경 ↑ / 발판당 최대 ↓ / 방향 최소차 ↑ |
| 개수 부족 | 최대 개수 ↑ / 링크 최소 간격 ↓ |
