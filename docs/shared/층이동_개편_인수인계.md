# 1. 구조

## 1.1 층 전환의 권위 = 씬에 배치하는 마커

`TraversalLink` 컴포넌트를 씬에 놓으면, Bake가 이걸 두 곳으로 굽는다.

| 대상 | 용도 | 게이팅 방식 |
|---|---|---|
| **NavMeshLink** | 평상시 길찾기 | NavMesh Area (`Leap` / `LeapTraversal`) |
| **그래프 링크** | **예측·following** | `agentMask` 직접 검사 |

**NavMesh는 연속 표면(평지·경사로)만** 담당하고, **불연속 전환(절벽·틈·큰 단차)은 마커만** 담당한다.

마커 종류는 3종이며 **하강은 항상 전 지상몹 허용**, 변수는 상승 권한뿐이다.

| 종류 | 하강 | 상승 |
|---|---|---|
| ① 일반 | 전 지상몹 | 전 지상몹 |
| ② 상승제한 | 전 지상몹 | **Traversal 특성만** |
| ③ 하강전용 | 전 지상몹 | 불가 |

게이트는 **링크가 아니라 진행 방향**에 걸리므로, 마커 하나가 **방향별 링크 2개**로 구워진다.

## 1.2 이동 = 정점 보장 탄도 + 속도 배분

```
apexY   = max(출발.y, 착지.y) + clearance      // 항상 확실히 솟는다
vy0     = sqrt(2·g·(apexY − 출발.y))
T       = t_up + t_down                        // 비행 시간은 물리로 결정(고정 틱 아님)
v_horiz = 수평거리 / T
```

그 위에 **속도 배분**을 얹는다(궤적 모양은 유지, 시간만 워핑):
- **상승** = ease-out → 초반 가속
- **하강** = ease-in → 막판 가속

`x = tick/flightTicks`, `u = ascend ? 1−(1−x)^p : x^p`, 그 `u`로 탄도식을 평가한다.
**닫힌 형식**이라 누적 오차가 없고 포크 재현이 보장된다.

주저·멈칫은 **링크 직선 길이 비례**(데드존 없음 — 짧아도 최소값, 가속형 곡선, 상한 클램프).

## 1.3 예측 그래프

예측은 월드를 포크해 sim을 그대로 돌리며, 그 안에서 `GraphPathfinder`를 쓴다
(NavMesh는 결정론적 포크 불가 — 계약 §8.3).

- **맵별로 구운 에셋**(`PredictionGraphAsset`)을 씬 이름으로 로드
- **없으면 코드 그래프(`CreateArena`, SampleScene 전용)로 폴백**
  → SampleScene은 굽지 않아도 기존대로 동작

# 3. Sim 자료구조

## 3.1 `EnemySim` 추가 필드
```csharp
int   traversalSlot;          // 점유 슬롯(-1 = 없음)
int   traversalPauseTicks;    // 이번 도약의 주저
int   traversalRecoverTicks;  // 이번 도약의 멈칫
float traversalClearance;     // 이번 도약의 정점 여유 ─┐ 비행 중 궤적 재구성에 필수.
float traversalGravity;       // 이번 도약의 중력      ─┘ 없으면 다른 아치로 풀린다
float personality;            // 개체 고정 개성값 0~1
```
`Personality(int id)`는 **순수 해시**(난수 스트림 아님, 상태 없음) → 포크 안전.

## 3.2 `PlayerSim` 추가 필드
```csharp
Vector3 lastGroundedPos;   // 접지할 때마다 갱신(PlayerMovement.Step)
```
적 추적 목표는 `grounded ? pos : lastGroundedPos`.
공중 좌표를 목표로 삼으면 `SamplePosition`(반경 4m)이 실패해 경로가 없다고 판정된다.
지면 투영(레이캐스트)이 아니라 이 방식인 이유는 **질의 비용 0**(포크 유리).

## 3.3 `WorldHash` 추가분
```csharp
MixV(w.player.lastGroundedPos);
// enemy — jumpEnd 다음
Mix (e.traversalSlot + 1); Mix (e.traversalPauseTicks); Mix (e.traversalRecoverTicks);
MixF(e.traversalClearance); MixF(e.traversalGravity);   MixF(e.personality);
```

## 3.4 `PathStep` 추가분
```csharp
float clearance, gravity;      // 궤적 파라미터(값이 아니라 파라미터를 넘겨 세 곳이 같은 함수로 푼다)
int   pauseTicks, recoverTicks;
int   slotCount; float slotSpread;
```

## 3.5 `ArenaNavLink` 추가분
```csharp
Vector3 traversalStartPosition;  // 도약 발판(코너 매칭용)
float   clearance, gravity;
int     pauseTicks, recoverTicks;
float   costDistance;            // 길찾기 비용(환산거리)
```
기존 `landingSlotCount`/`landingSpread`가 이제 실제로 쓰인다.

**미지정 링크 자동 보정**: `clearance <= 0`인 traversal 링크는 `GraphPathfinder.FromBake`가
길이 기반 기본값을 채운다 → 손으로 짠 그래프(`CreateArena`)도 정상 동작한다.

## 3.6 튜닝 상수 (★ static = 예측 중 변경 금지)
```csharp
// SimConfig
TraversalGravity 22 / MinClearance 0.6 / ClearanceRatio 0.18 / MaxClearance 4      (const)
★ TraversalAscendShape 1.5 / TraversalDescendShape 1.9                            // 속도 배분
★ TraversalPauseMin 3 / PauseMax 22 / RecoverMin 4 / RecoverMax 30
★ TraversalLengthRef 14 / TraversalLengthExp 1.9
TraversalSlotMax 6 / SlotGapMul 2.2 / LinkCapacity 2                               (const)

// AIConfig — 전부 static
★ SeparationRadius 1.6 / SeparationWeight 0.9 / SeparationMaxPush 2.5 / SeparationScaleMin 0.55
```

# 4. 동작

## 4.1 `EnemyMovement`
```csharp
// 시그니처 변경 — 슬롯 점유 판정에 다른 적들을 봐야 해서 월드 전체가 필요
Step(ref SimWorld w, int selfIndex, Vector3 sep, in SimServices svc, float dt)
```
- **Pause → Airborne → Recovery**. 주저·멈칫이 0이면 그 단계를 **건너뛴다**.
- **Airborne**: 매 틱 위치를 닫힌 형식으로 직접 계산(누적 적분 아님).
  시작 시 복사해 둔 `traversalClearance/Gravity`로 재구성해 **계획한 아치를 유지**한다.
- **슬롯 점유·정원 대기**: 별도 자료구조 없이 적 배열을 훑어 판정
  (`activeTraversalLinkId` + `traversalSlot`) → 포크 시 자동 복사. 순서는 배열 인덱스 = 결정론적.
- **착지 검증**: 도약 시작 시 1회 `SampleGround` + `CanOccupyCapsule`,
  실패하면 정확한 착지점으로 폴백. (충돌 질의 2회 — 매 틱 아님, NavMesh 아님)
- **분리 스티어링**: `personality`가 세기를 `SeparationScaleMin ~ 1`배로 가른다.

## 4.2 `EnemyAI`
```csharp
if (e.traversalPhase != TraversalPhase.None)
{ EnemyMovement.Step(ref w, i, Vector3.zero, in svc, dt); return; }
```
**도약은 시작하면 착지까지 커밋** — 공중에서 상태머신이 위치를 덮어쓰지 못하게 한다.

## 4.3 `SimStep`
`ClampToNavMesh` 제외 조건에 `traversalPhase != None` 추가.
공중 궤적은 걷기 가능 표면 밖이라, 되당기면 탄도와 충돌한다.
`Separate`는 이미 `Airborne`을 제외하고 있었다(변경 없음).

## 4.4 `GraphPathfinder`
- **간선 비용**: `costDistance`가 있으면 그 값, 없으면 직선거리.
  도약을 직선거리로 두면 **공짜로 보여** 평상시(보정됨)와 정반대 판단을 한다.
- **공간 색인**: `NearestNode`를 격자 해시로. 노드 24개 이상에서 자동 활성.
  동률 해소는 `nodeId` 오름차순으로 동일 → **결정론 보존**.
- `NextStep`이 탄도 파라미터·슬롯 정보를 함께 실어 보낸다.

## 4.5 `NavMeshPathfinder` (평상시 전용)
- 낙차 기하 자동판정(`DropDetect`) 폐기
- `agentMask` → areaMask 유도. Traversal이 아니면 `LeapTraversal` Area 배제
- 마커 진입은 **경로 코너 좌표 매칭**으로 판정(연속 중복 코너 병합 + "발판 위에 서 있음" 별도 판정)

# 7. 지켜야 할 제약

| 제약 | 이유 |
|---|---|
| **`NavMeshLink.width = 0`** | 폭이 있으면 NavMesh가 진입점을 변 위 아무 곳에나 잡아, 경로 코너가 링크 좌표와 폭/2만큼 어긋나 진입 판정이 실패한다 |
| **검증 캡슐은 일반몹 기준** | 대형몹(높이 4.3m)으로 검증하면 층간이 낮은 실내에서 거의 모든 링크가 무효가 된다. 대형이 꼭 지나야 하는 링크만 `validateForLargeMobs` |
| **마커 끝점은 NavMesh 안쪽** | NavMesh는 에이전트 반경(0.5m)만큼 가장자리가 깎인다. Bake가 `SamplePosition`으로 당기지만, F2 시각화에서 **끝점이 빨강이면 옮겨야 한다** |
| **NavMesh Area 필요** | `Leap`/`LeapTraversal`이 없으면 코드가 0(Walkable)으로 폴백 → **몹별 게이팅 무효**. `Tools/층이동 링크/NavMesh Area 생성` 후 Play 재시작 |
| **맵·마커 수정 시 재굽기** | 예측 그래프는 에셋이라 자동 갱신되지 않는다. 안 구우면 **예측만 옛 지형**을 본다 |
| **노드 수 = 성능** | `NextStep`은 예측에서 적×틱마다 불린다. 공간 색인이 있지만 Floyd-Warshall은 O(V³)이라 굽기 비용이 커진다 |

# 8. 미완

## 8.1 공중몹
Flying은 마커를 쓰지 않는다. 별도 3D 항법은 **범위 밖**.

## 8.2 예측 경로 품질
평상시는 NavMesh 연속 최적경로, 예측은 노드 기반이라 **절대 경로가 다르다**.
노드 밀도를 올리면 품질↑ 성능↓ 정면 트레이드오프.
Following은 그래프로 재생하므로 **"예측한 대로 실행"은 보장**된다.

**Scene 뷰**: 끝점 드래그 / 궤적 꼭대기(노란 구) 드래그 = clearance 수동 / "자동으로 되돌리기" /

NavMesh 시각화에서 마커 끝점 **빨강 = 면 밖**.

## 9.1 자동 배치 창
낙하형 + **간극형**(같은 높이인데 사이가 끊긴 곳) 탐지. **[분석]** 시 Scene 뷰에 샘플된 면(초록 점)과 후보 선 표시.

| 증상 | 조절 |
|---|---|
| 다리·좁은 발판에 점이 없음 | 격자 간격 ↓ |
| 점은 있는데 링크 없음 | 최소 낙차 ↓ / 가장자리 낙차 ↓ / 틈 깊이 ↓ |
| 비슷한 패턴 반복 | 같은 발판 반경 ↑ / 발판당 최대 ↓ / 방향 최소차 ↑ |
| 개수 부족 | 최대 개수 ↑ / 링크 최소 간격 ↓ |

## 9.2 예측 그래프 굽기 창
**Play 중에만** 동작(NavMesh가 런타임 생성).

| 옵션 | 기본 | 비고 |
|---|---|---|
| 마커 끝점 노드로 승격 | 켬 | 끄면 발판이 노드와 어긋나 엉뚱한 지점에서 도약 |
| 끝점 병합 반경 | 2m | 노드 수 감소 |
| 지형 보충 간격 | 12m | 0 = 마커 끝점만 |
| 최대 연결 거리 | 16m | |
| 직행 가능 검사 | 켬 | 끄면 협곡 건너편끼리 연결됨 |
| 노드당 최대 이웃 | 6 | |

**[분석]** 리포트: 노드·링크 수, **연결 성분 수**, 고립 노드, Floyd-Warshall 예상 연산량.
