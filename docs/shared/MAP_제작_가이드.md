# 맵 제작 가이드

이 프로젝트 맵을 만드는 방식·워크플로 정리. (연출·전투 등은 별도 문서.)

---

## 1. 맵 종류

| 종류 | 정의 |
|---|---|
| **아레나** | 진입하면 **자동문이 가두고**, **웨이브로 몹 스폰**, **전멸할 때까지** 안 열림. 방이든 야외든. |
| **복도** | 아레나 사이. **안 가둠**, 전멸 강제 아님. 좁을 수도 넓을 수도(작은 연구실·큰 홀도 "안 가두면 복도"). 몹은 **이미 배치**(근접 시 스폰 = 최적화·버그방지). 학습/완급 공간. |
| **최종 전장** | 탁 트인 복잡한 야외 아레나. |

→ 아레나/복도 구분 기준 = **"웨이브로 가두느냐."**

---

## 2. 제작 워크플로 (블록아웃 → NavMesh → 스킨)

**이게 맵 제작의 뼈대. 순서 지킬 것.**

1. **블록아웃(그레이박스)** — 단순 박스로 **콜리전·레이아웃·크기**를 직접 만듦. 치수 자유(에셋 크기에 안 묶임). 여기서 방·복도 크기·동선 확정.
   - 도구: `Tools > 맵 부속`(MapPartsTool) 또는 ProBuilder.
2. **NavMesh 베이크** — 이 **깨끗한 그레이박스에서** 베이크. (평소 몹 길찾기 = 이 NavMesh.)
3. **플레이테스트** — 동선·전투·페이싱 검증. (아트 없이.)
4. **비주얼 에셋 드레싱** — 모듈 에셋을 블록아웃 위에 덮되 **에셋 콜라이더는 끔**.
5. **라이팅·포스트** — 무드.

> 프로 표준: **그레이박스로 게임플레이 먼저 완성 → 아트는 나중.** 처음부터 아트 붙이면 수정 지옥.

---

## 3. 콜리전 vs 비주얼 메시 (분리)

- **콜리전(그레이박스)** = 게임 규칙·충돌·**NavMesh 소스**. (깨끗한 단순 형상.)
- **비주얼 에셋** = 눈에 보이는 껍데기. **콜라이더 off.**
- **왜 분리?** 정교한 에셋 메시를 그대로 콜리전에 쓰면 **끼임·틈·NavMesh 버그** 발생. 깨끗한 블록아웃이 충돌·나비를 담당해야 안정적.
- 단순 물체는 같이 써도 되지만(비주얼=콜리전), **게임플레이 중요 구역은 반드시 분리.**

---

## 4. 에셋 크기 제약 우회

- **못 하는 것**: 에셋 하나를 원하는 크기로 **스케일(늘리기)** → 텍스처·비율 깨져 티남. 고퀄에선 금지.
- **되는 것**: **모듈러 킷 = 타일링 설계.** 조각을 **여러 개 이어붙여** 원하는 크기 제작. (벽 조각 2개 = 8m 벽.) → 크기에 안 묶임.
- **딱 맞는 조각 없는 자리**:
  - **그레이박스 필러**(같은 톤 텍스처 입힌 박스) — 어두운 무드에 잘 묻힘.
  - **킷배시**(조각 잘라 조합).
  - **ProBuilder**로 그 스타일 맞춰 커스텀 조각 제작.

---

## 5. 에셋 (맵용)

- **리얼 계열 사이파이/사이버펑크 모듈러 킷 + 소품.** (Synty 저폴리 만화풍 ✗ — 룩 안 맞음.)
- 검색어: `sci-fi/cyberpunk modular interior`, `sci-fi corridor kit`, `neon signs`, `sci-fi props (pipes/cables/monitors)`.
- 마켓: Unity Asset Store, Fab.
- 사용 시 **콜라이더 off** (§3).
- **한 스타일로 통일** (몹·소품·환경 룩 일치).

---

## 6. 길찾기 연동 (맵마다)

- **평소 몹 길찾기 = NavMesh** — 어떤 지오메트리든 **자동 베이크**. 새 맵도 그냥 됨.
- **예측(F) = 고정 그래프** — **맵마다 별도 그래프 필요.** 현재는 코드큐브용 하드코딩(17노드)이라 새 맵엔 안 맞음.
  - 그래프 굽는 방식 = **D(하이브리드)**: NavMesh에서 걷기 자동 + 드롭/부스터/자동문 등 특수 링크는 에디터 수동. (구현은 후속.)
- → **맵 확정 후 그 맵의 예측 그래프를 갱신/생성**해야 예측이 정확. (평소 플레이는 NavMesh라 그래프 없어도 됨.)
