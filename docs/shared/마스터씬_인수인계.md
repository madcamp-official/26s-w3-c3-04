## 0. 한 줄 요약

`Assets/_Project/Scenes/Level_Main.unity` 에 **Arena_1~4 콘텐츠 프리팹 + 복도**가 배치돼 있고,
**Arena_1~3은 마커·NavMesh·웨이브·방·게이트가 전부 세팅 완료**. **Arena_4는 지형만 있는 미완성.**
NavMesh는 **아레나별로 콘텐츠 프리팹 안에서** 굽고, 예측 그래프만 **마스터에서 통합**해 굽는다.

## 1. 아키텍처 (중요 — 이게 전제다)

### 콘텐츠 프리팹 = 아레나의 모든 것
`Assets/_Project/Prefabs/Arenas/Content/Arena_N_Content.prefab` 안에 아레나 고유의 것이 전부 들어 있다:
지형, Fan 스폰, **웨이브(ArenaWaves+WaveRunner)**, **층이동 마커**, **NavMeshSurface+구운 데이터**,
**방 인식 박스(BoxCollider+ArenaRoom)**, **ArenaLights**, **게이트(ArenaGate)**.

→ **프리팹을 고치면 마스터에 자동 반영된다.** 마스터를 열 필요 없음. 예측 그래프만 예외(§4).

### 편집은 아레나 씬에서
각 `Arena_N.unity`는 "시스템 + 콘텐츠 프리팹 인스턴스" 상태다. **이 씬이 각 아레나의 편집장이다:**
1. `Arena_N.unity` 를 연다 (단독 플레이 테스트도 됨)
2. 콘텐츠 인스턴스 안에서 고친다
3. 콘텐츠 루트 선택 → 인스펙터 Overrides ▸ **Apply All**

> ⚠ **프리팹 편집 모드(더블클릭)에서는 층이동 마커 자동배치·NavMesh 굽기가 안 된다.**
> 프리팹 모드는 격리된 물리 씬이라 `Physics.Raycast`가 아무것도 못 맞힌다("면 0개"). **반드시 아레나 씬에서 할 것.**

### 마스터에 있는 것
`_Cameras`, `_Gameplay`, `PlayerSpawnPoint`, 복도 조각(`C_0`~`C_3` 아래 `Corridors_allRounder_Content` ×10, `Floor_01` ×34), 아레나 콘텐츠 인스턴스 4개.
- **씬에 `Main`이 없어도 된다** — [Main.cs](../../PrecogPrototype/Assets/_Project/View/Bootstrap/Main.cs) L487 `[RuntimeInitializeOnLoadMethod]`가 Play 시 `[Main]`을 자동 생성한다.

## 4. 무엇을 고치면 무엇을 다시 구워야 하나

| 고친 것 | 다시 구울 것 |
|---|---|
| 웨이브 구성(ArenaWaves) | **없음.** 순수 데이터 → 다음 Play에 즉시 반영 |
| 게이트·존박스·조명 | **없음.** 컴포넌트라 자동 반영 |
| 층이동 마커 추가/이동 | **마스터에서 예측 그래프만** 다시 굽기 (NavMeshLink는 Play마다 마커에서 자동 생성) |
| 지형(콜라이더) 변경 | 그 아레나 씬에서 **NavMesh** → 마커 재배치 → 마스터에서 **예측 그래프** |

**예측 그래프 굽는 법**: `Level_Main` 열고 `Tools/층이동 링크/예측 그래프 굽기` → **[분석] 먼저** →
높이 상한 27.5 / 병합반경 3.0 확인 → [굽기].

## 5. ⚠ 알려진 문제·미해결

1. **Arena_4 미완성** — 지형만 있다. 필요한 것: Fan 배치 → 씬에서 마커 자동배치 → 드롭링크 →
   NavMesh(콘텐츠 안 Surface) → 웨이브 → 방 컴포넌트(⑤) → 게이트 배선. 그 후 예측 그래프 재굽기.
2. **Arena_4 게이트 오프셋 19.5m가 과할 수 있음** — `Gate` 프리팹 렌더러 전체 바운드라 **프레임(고정부) 포함 값**이다.
   문짝만 움직이려면 `door`를 실제 문짝 자식으로 지정하고 오프셋을 줄일 것.
3. **문이 위로 열려 천장을 뚫을 수 있음** — 씬 뷰에서 게이트 선택 시 하늘색 기즈모가 열림 위치. 걸리면 오프셋 조정.
4. **복도에 NavMesh가 없다** — 아레나별로 구웠기 때문. 몹은 아레나 밖으로 못 나간다(설계상 수용).
   예측 그래프 **"연결 성분 14개 · 고립 노드 9개" 경고의 원인**이며, 같은 이유로 무시해도 된다.
5. **게이트가 닫혀도 NavMesh 경로는 게이트 너머로 계획될 수 있다** — 게이트 콜라이더가 물리적으로는 막지만
   NavMesh는 그대로다. 문제가 되면 문에 `NavMeshObstacle`(carve) 추가 검토.
6. **미검증** — 존 박스 크기가 시각적으로 적절한지, 게이트 문 크기·위치, 웨이브 5마리 분산이 의도에 맞는지.
   **플레이 검증 안 함**(에디터 세팅만 완료).

## 6. 플레이 검증 절차

`Level_Main` Play → 복도 스폰 → Arena_1 진입 시:
입구 게이트 닫힘 + 조명 빨강 + 웨이브 1 시작 → 전멸 시 웨이브 2 → 전멸 시 출구 열림 → 다음 복도 → …

안 되면 확인 순서: ① ArenaRoom 존 안에 실제로 들어갔는가(기즈모) ② WaveRunner에 config 있는가
③ Fan 위치가 아레나 안인가 ④ Console에 `[ArenaRoom]` 경고가 있는가.
